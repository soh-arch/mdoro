# 0047. テストは本物のアプリの中で走る。だから外へ出るものは全部せき止める

- **状態**: proposed
- **決定日**: —（人間の承認待ち）
- **決定者**: 人間
- **反映**: 未（コードには既に在る。**32件の根拠が台帳の2行にしかない、という状態を解く**）
- **関連**: [0018](0018-diagnostic-log-policy.md) / [0013](0013-pbxproj-is-owned-by-xcode.md)

## 文脈

**`xcodebuild test` は `MdoroMac.app` と `MdoroiOS.app` を本物として起動する。**

**ホストは外せない。**両方のテストターゲットがアプリのモジュールを `@testable import` しており、
**アプリ自身の記号を解決するには `BUNDLE_LOADER = $(TEST_HOST)` が要る。**

**つまりテストは、アプリのバンドル識別子の下で、本物のアプリとして走る。**

⚠ **そして普通に起動したアプリは、自分のプロセスの外へ出る。**
**通知を配り、読者が使っていた画面の前にウィンドウを引き出し、LAN に Bonjour を広告し、
読者の `Task.md` を監視する。**

**所有者は、それが自分の機械で起きるのを見た。**
⚠ **公開されれば、貢献者全員の機械とネットワークで、スイートを走らせるたびに起きる。**

**この事実の上に、いま32件のコードが立っている**（POL-165 の2便目で14件、3便目で18件）。

| 何 | いくつ |
| :---- | :---- |
| 継ぎ目（本物の代わりに無害なものを差し込む口） | **5つ** —— `SessionNotifying` / `IdleSleepGuarding` / `DeviceTokenStoring` / `TokenStoring` / `TestHost` の門 |
| Scene に効くもの | **3つ** —— `MenuBarExtra` を出さない（`showsMenuBarExtra`）／ウィンドウを起動時に出さない（`.defaultLaunchBehavior(.suppressed)`。**シーンは残す。テストバンドルがこのアプリに読み込まれるため**）／起動そのものを止める門 |
| 守っている検査 | `TestHostDetectionTests`（Mac・iOS の両ターゲット） |

⚠ **この事実は、条文にも `docs/decisions/` にも無い。**
**根拠として引けるのは `docs/PUNCHLIST.md` の2行（POL-047 / POL-053）だけである。**

**POL-165 が「台帳は恒久の参照対象として相応しくない」と定めた、まさにその形である** ——
**碇を付け替える作業の途中で、付け替え先が無いものが最も多く集まった場所がここだった。**

## 判断

**テストは本物のアプリの中で、そのバンドル識別子の下で走る。これは前提であって、直す対象ではない。**

**そのうえで、プロセスの外へ出るものは、すべてせき止める。**

- **本物に触れる部分には継ぎ目を置き、テストでは無害なものを差し込む。**
  **アプリ側に「これはテストのときは」という分岐を書かない。**
- **アプリの2つの入口は、起動する前に `TestHost` に訊く。**訊く場所は**1箇所にまとめる** ——
  **同じ条件の写しが2つあれば必ず片方が腐り、腐ったほうは誰も走らせないほうである。**
- **起動済みのモデルが要るテストは、自分で組み立てる。**

## 理由・設計意図

**守っているのは、このリポジトリのコードではない。読者の機械である。**

**通知は読者の通知センターに出る。**アイドルスリープの抑止は**機械全体を眠らせなくする**
（`ProcessInfo.beginActivity` はプロセスの中に留まらない）。**Keychain はアプリのバンドル識別子で引かれるので、
テストが書けば利用者の項目に書く。**`UserDefaults` も同じ識別子を見る。
**Bonjour の広告は LAN に出る。**ウィンドウは読者が見ていた画面の前に出る。

⚠ **どれも「テストが失敗する」形では現れない。**
**スイートは緑のまま、読者の機械に副作用だけが残る。**

**実例がある**（2026-09-16）: **Keychain のダイアログを調べたとき、
「テストは利用者の Keychain に触っていない」と言い切れたのは `TokensKeptNowhere()` が在ったからである。**
⚠ **その設計の理由は、台帳の行にしか書かれていなかった。**
**調べた本人が、根拠を台帳から掘り出すことになった。**

**なぜ条文ではないのか。**
⚠ **これは「Mdoro が何をするか」ではなく「テストをどう走らせるか」である。**
**`docs/SPEC.md` は利用者に向けた要件の文書であり、この判断はその役目の外にある。**

**なぜ台帳では足りないのか。**
**`docs/PUNCHLIST.md` は流動的な運用文書で、行は閉じれば読まれなくなる。**
⚠ **32件のコードが、閉じた行を指し続けることになる。**

## 影響

- **コード**: 継ぎ目5つと Scene 2つ。**すべて既に在る。この記録は新しい実装を要求しない。**
- **碇の打ち先**: POL-165 の付け替えで宙に浮いた32件。**検証役が3便目で独立に抜き取った例** ——
  `ListenerFoldingTests.swift:7`・`RecordedNotifications.swift`・`RecordedSleepGuard.swift`・
  `TestHostDetectionTests.swift`（2ターゲットとも）・`ServerPresenceWiringTests.swift`。
- **新しい継ぎ目を足すときの判断基準になる** —— ⚠ **「本物に触れるか」ではなく「読者の機械に何かが残るか」で決める。**
- ⚠ **`TestHost` が読む2つの環境変数は、Apple の文書のどこにも現れない**（`docs/PLATFORM.md`）。
  **約束されたものではない。**Xcode か `xcodebuild` が起動の仕方を変えれば、
  **門は何も言わずに開く。**`TestHostDetectionTests` が守っているのはそこである。

## 出典と確度

- **事実**: ホストが外せないこと（`@testable import` と `BUNDLE_LOADER`）。`TestHost.swift` に根拠が書かれている。
- **実測**: 所有者が自分の機械で観測した（2026-08-28・POL-047） ——**「数秒おきに通知が飛び交う」「ウィンドウが急に最前面に来る」。**
- **実測**: テストが本物のスリープ抑止のアサーションを取っていた（POL-053）。`record()` でセッションを走らせると `IdleSleepGuard.begin()` が実機に掛かる。
- **数え**: 32件（実装役が2便で数え、検証役が3便目で独立に抜き取った。2026-09-16）。
- ⚠ **未検証**: **2つの環境変数が将来も同じであるかは、Apple が何も約束していない。**
  **検出が外れたときに何が起きるかは、`TestHostDetectionTests` が落ちる形でしか分からない。**
