# 0017. 通知音はシステムサウンドを流用する

- **状態**: accepted
- **日付**: 2026-08-26

## 文脈

REQ-NTF-006（SHOULD）は「通知音を数種類から選択でき、無音（触覚のみ）も選べること」を求めるが、
**具体的な音源を定めていなかった**（旧 OPEN-001）。
`Preset.notificationSound` には `default` / `chime` / `bell` / `wood` / `silent` の5種があるが、
音源が未決だったため、工程4の実装では無音以外をすべて既定音にまとめ、
設定画面にも「既定」と「無音」しか出していなかった。

選択肢は2つだった。独自音源を用意するか、OS のシステムサウンドを流用するか。

## 判断

**macOS / iOS のシステムサウンドを流用する。独自音源は同梱しない。**

- `chime` → `Glass.aiff`、`bell` → `Submarine.aiff`、`wood` → `Pop.aiff`
  - 当初 `wood` に当てた `Tink.aiff` は **0.56 秒の極めて小さなチック音**で、実機で「鳴らない」と報告された。通知音として成立しないため差し替えた（2026-08-27）
- `default` は OS の既定通知音、`silent` は音を鳴らさない
- **設定画面で選択した音を試聴できるようにする。** 名前だけでは違いが分からない
  - ~~ただし `default` は OS が持つ音でファイルとして指せないため、**試聴の対象外**とする~~
    → **[0019](0019-sound-preview-is-a-real-notification.md) で改めた。** 試聴は実際の通知を1件送る方式とし、
    既定音も確認できるようにした。音源を直接鳴らす試聴は通知経路を通らず、
    「試聴では鳴るのに本番では鳴らない」を見逃す原因になった（2026-08-27）

## 理由・設計意図

**独自音源を作るだけの必然性がない。** このアプリの通知は「区切りが来た」ことを伝えるだけで、
ブランドを主張する場面ではない。音源の制作・ライセンス・容量を抱える理由がない。

**聞き慣れた音のほうが用途に合う。** システムサウンドはユーザーが他のアプリで既に耳にしている。
初めて聞く音より、「何かが終わった」と直感的に結びつきやすい。

**試聴を要求するのは、名前が音を説明しないためである。**
「チャイム」「ベル」「ウッド」は分類でしかなく、選ぶ前に鳴らせないと総当たりで試すことになる。

## 影響

- 要件: REQ-NTF-006（音源をシステムサウンドに確定、試聴を追加）
- コード: `MdoroCore/Preset.swift` の `NotificationSound`（`systemSoundFileName` / `displayName`）、
  `PomodoroMac/Services/NotificationScheduler.swift`、`Views/PresetEditorView.swift`
- iOS 側（工程7）でも同じ列挙を使う。**iOS には `/System/Library/Sounds` が存在せず、
  この対応表は macOS 専用であることが判明した**（2026-08-27 確認）。iPhone 側の扱いは OPEN-016
- 仕様書 v2.6.1 の 0.9 節に記録。OPEN-001 を解決済みとする

## 出典と確度

- **事実**: 判断はプロダクトオーナーによる（2026-08-26、「通知オンはシステムサウンドを流用してください」）。
  macOS 側のファイル名は `/System/Library/Sounds` の実在を確認したもの。
- **推測**: 「独自音源を作る必然性がない」「聞き慣れた音のほうが合う」という理由づけは
  Claude Code による整理である。
