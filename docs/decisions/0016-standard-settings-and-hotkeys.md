# 0016. 標準的な設定項目は満たす。グローバルショートカットは既定を持たない

- **状態**: accepted
- **日付**: 2026-08-26

## 文脈

REQ-UIX-033（SHOULD）はグローバルショートカットで「一時停止 / 再開」ができることを求めているが、
**どのキーに割り当てるかを定めていない**。常駐アプリが OS 全体のキーを押さえるため、
他アプリと衝突すると原因の分かりにくい不具合になる。実装を止めて判断を仰いだ（旧 OPEN-013）。

あわせて、工程4では「SHOULD だから」「実装が煩雑だから」を理由に
標準的な設定項目をいくつか見送っていた。

## 判断

**1. グローバルショートカットは既定を持たない。ユーザーが任意の組み合わせを割り当てる。**

- 初期状態は「未設定」。何も登録しない。
- 修飾キーを含まない割り当ては受け付けない（単独キーを奪うと文字入力ができなくなる）。
- 他アプリに専有されていて登録できなかった場合は、設定画面にその旨を示す。
- **アクセシビリティ権限を要求しない手段で実装する。**

**2. 標準的な設定項目は、実装が過度に煩雑でない限り満たす。**

一般的な Mac アプリが持っている設定は、仕様書に明記がなくても用意する。
見送る場合は、理由（実装コストが釣り合わない／スコープ外の原則に触れる）を残す。

## 理由・設計意図

**既定を置かないのは、衝突したときに気づけないからである。**
グローバルホットキーは、押しても何も起きないのではなく「別のアプリが反応する」形で失敗する。
ユーザーが自分で割り当てたなら、衝突しても原因を追える。こちらが勝手に決めた既定では追えない。

**アクセシビリティ権限を要求しない**のは、機能と要求の釣り合いが取れないため。
`NSEvent.addGlobalMonitorForEvents` はこの権限を要り、
「タイマーを一時停止したいだけ」の機能に対して
「このアプリにコンピュータの制御を許可しますか」を出すことになる。
`RegisterEventHotKey`（Carbon）は権限なしで動くため、こちらを使う。

**標準的な設定項目を満たすのは、仕様書が UI の網羅リストではないからである。**
仕様書はこのアプリに固有の要件を定めるものであり、
「ログイン時に起動する」のような、どのアプリにもある項目まで列挙してはいない。
記載がないことは「不要」を意味しない。記載がないなら、その分野の標準に合わせる。

## 影響

- 要件: REQ-UIX-033（既定なし・任意設定・権限不要を明記）、
  9.3 に `pauseResumeHotKey`（既定 未設定）と `launchAtLogin` を追加
- コード: `MdoroCore/HotKeyBinding.swift`、`PomodoroMac/Services/HotKeyCenter.swift`、
  `LoginItem.swift`、`Views/HotKeyRecorderView.swift`
- 適用範囲: 「一時停止 / 再開」のみをグローバルに割り当てる。
  中断・リセットは誤爆すると取り返しがつかないため、メインウィンドウに留める（REQ-UIX-031 と同じ理由）
- 仕様書 v2.6.1 の 0.9 節に記録

## 出典と確度

- **事実**: 判断はプロダクトオーナーによる（2026-08-26）。
  「規定は無効で、任意のホットキー設定が可能なように」「実装が面倒な項目以外は基本的に
  アプリの標準的な設定項目は満たしておきたい」との指示。
  実装後、⌃⌥P を割り当てて一時停止・再開の双方が動くことを実機で確認した。
- **推測**: 「衝突したときに気づけない」「権限と機能の釣り合い」という理由づけは
  Claude Code による整理であり、プロダクトオーナーがこの理由を述べた記録はない。
