# 0033. ログの保存先が未設定の間は、記録しない

- **状態**: accepted
- **日付**: 2026-08-28
- **反映**: 未（工程13c で SPEC v2.10 へ）

## 文脈

`logFolderPath` の既定値は「未設定」である（9.3）。**公開後は、すべての利用者がこの状態から始まる。**

ところが条文は「一度設定した後」を前提に書かれていた。`logFolderPath` が未設定のまま
セッションが確定に至ったとき、ログをどう扱うかが条文から引けない。
REQ-LOG-002 が扱うのは「作成先ディレクトリが**存在しない**」であって、「**未設定**」は別の状態である。

キューに積む解釈を採ると、REQ-LOG-005（3回失敗した時点で利用者に通知）により
**新規利用者は3セッション目で書き込み失敗の通知を受け取る。**
REQ-LOG-019 により、キューに入った時点で `committedAt` が立つため、
未設定のまま何日も使われた後にフォルダを設定すると、**過去の全セッションが一括で流し込まれる。**

作者1人が使う限り、初日に1回設定して終わる話であり、条文がなくても困らなかった。
公開後は全員がここを通る。公開前の監査（POL-020）で検出した。

## 判断

**`logFolderPath` が未設定の間は、ログの書き込みを試みない。記録もしない。キューにも積まない。**

| 項目 | 挙動 |
| :---- | :---- |
| セッションの進行・確定・周回数の加算 | **通常どおり行う。** タイマーはログ無しで完全に動作する |
| ログの書き込み | **試みない。** 記録は残らない |
| REQ-LOG-005 の再試行キュー | **対象外。** 未設定は失敗ではない |
| 3回失敗時の通知 | **出さない**（そもそも失敗していない） |
| 画面表示 | **保存先が未設定であることを示す。** 黙って記録しないことはしない |

**未設定は、失敗ではなく未構成である。** 両者を同じ経路で扱わない。

## 理由・設計意図

**タイマーはログ無しで動くべきものである。** 状態の正本は Mac にあり（[0001](0001-mac-as-single-source-of-truth.md)）、
ログは実績の記録であって動作の前提ではない。設定を終えていない利用者からタイマーを取り上げない。

**新規利用者がいきなり失敗通知を受け取るのは、最悪の初期体験である。**
3セッション目に「書き込みに失敗しました」と出たとき、利用者は自分が何を壊したのかを探すことになる。
実際には何も壊れておらず、まだ設定していないだけである。

**後から一括で流し込まない。** 利用者がフォルダを選んだ瞬間に、
選んだ覚えのない過去数日分がファイルへ書き込まれる。挿入のみの原則（[0002](0002-task-md-read-only.md)）には
違反しないが、**利用者が意図していない書き込みが一度に起きることに変わりはない。**
`docs/CONTEXT.md` §1 の「弁える」に照らして採らない。

**記録が残らないことは、黙っていなければ許容できる。** `docs/CONTEXT.md` §2「失敗を黙らせない」の
本体は、**起きなかったことを起きたように見せないこと**である。画面に未設定を示していれば、
利用者は記録が残っていないことを知っている。

## 影響

| 対象 | 内容 |
| :---- | :---- |
| REQ-ERR-001 | 事象に「**未設定**」を加える。対応の「**再**選択導線」は、未設定時は「選択導線」とする |
| REQ-LOG-002 | 「`logFolderPath` が未設定の間は書き込みを試みず、キューにも積まないこと。設定を促す表示を出すこと」を追記 |
| REQ-LOG-005 | 再試行キューの対象が「書き込みの失敗」であり、**未設定はこれに当たらない**ことを明記 |
| 第11章 | **波及しない。** キューに積まないため、キューの永続化（REQ-PER-001）に新しい要求は発生しない |
| 要件数 | **242 のまま。** 既存条文の書き換えのみで、新設しない |

`taskFilePath` の未設定については REQ-ERR-001 の書き換えで足りる。
タスクが選べないだけで、タイマーは動き、ログにはタスク名なしの行が残る（REQ-LOG-023 の
`selectedTaskSnapshot` が空である場合の扱いは既存条文で定まっている）。

## 出典と確度

- **事実**: 判断は 2026-08-28 のプロダクトオーナーの選択（提示した3案のうち「積まない」を採用）。
- **事実**: 3セッション目に通知が出ること、`committedAt` がキュー投入時点で立つことは、
  REQ-LOG-005 / REQ-LOG-019 の条文と v2.6.1 の改訂履歴（キューの永続化を明記した項）による。
- **推測**: 「未設定は失敗ではなく未構成である」という言い方は、判断内容からの再構成であり、
  プロダクトオーナーがこの言葉で説明したという記録はない。
