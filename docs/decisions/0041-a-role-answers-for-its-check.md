# 0041. 線は「どのモデルか」ではなく「何の権限があるか」で引く

- **状態**: accepted
- **日付**: 2026-09-03
- **反映**: コードのみ（条文の変更を伴わない。運用・体制の判断）

## 文脈

**このレコードは [0011](0011-claude-code-as-orchestrator.md) の一部を覆す。** 覆すのは**外部AIの位置づけ**である。0011 側の該当箇所には、すべてこのレコードへの参照が付いている ——
「判断」節の引用ブロックの「外部AIは、必要時の設計相談または監査に限定し」、
「実務上の意味」の「旧 PM（Cowork 側の Claude）は今後、設計相談と監査のみ」と
「外部AIの意見が直接リポジトリに入ることはない」、
「理由・設計意図」の「外部AIの意見を人間経由に限定する」。
**0011 の他の判断は有効なままである**（`一部置換` の印は 0011 側のフロントマターにある）。

0011（2026-08-25）は、**リポジトリ外の Claude（Cowork 側）が PM 兼実装担当として動き、正本がリポジトリの
外にあった体制**を畳むために書かれた。0011 の「文脈」は、そこで起きうることを「**外部AIの提案がそのまま
リポジトリの正本に入りうる構造だった**」と記している。

0011 の「外部AI」は**その上流だけを指していない。** 同レコードは「プロダクトオーナーが外部AIに相談した結果」
——**書き込む立場ですらない相談相手**——も同じ線の内側に置き、「相談すること自体は有用だが」と断ったうえで
人間経由に一本化している。**線は「Anthropic の外かどうか」ではなく「リポジトリの外か」で引かれていた。**

**いま問題になっているのは別のことである。** 検証役（`.claude/agents/reviewer.md`）の基盤モデルに
Anthropic 以外を使うことを検討している。これは**上流ではなく、役として使う道具**の話である。

0011 の条文をそのまま読むと、**役を別ベンダーのモデルで動かした瞬間に「外部AIの意見が直接リポジトリに入る」
形になり、禁止に触れる。** 実態と合っていない。

## 判断

**サブエージェントはどのモデルで動いてもよい。** 「どこの製品か」ではなく、**何の権限があるか**で線を引く。

| 事項 | 決定 |
| :---- | :---- |
| **完了承認** | **サブエージェントに権限は無い。** どのモデルで動いていても同じ。**「指摘なし」は merge の許可ではない** |
| **検証役の出力** | **指摘の列挙である。** 採否はオーケストレーターが判断し、**採らないなら理由を1行残す** |
| **責任の範囲** | **検証役は自分の検証に責任を持つのであって、成果物全体の品質に責任を持つわけではない。** 通したものが後で壊れたとき、**検証役の失敗と決めつける前に、軸の選び方と道具の届き方を疑う** |
| **正本の更新** | **サブエージェントは `docs/` の正本を更新しない。** **（推測）**上と同じく、0011 の主語を広げたものである（更新するのはオーケストレーターである。**`CLAUDE.md` の役の表では、人間もオーケストレーターも「役」である** —— だから「役は」と書くと両方を巻き込む） |
| **実装指示** | **サブエージェントは他の役に実装を指示しない。** 割り当てるのはオーケストレーターである。0011 が否定した3つの権限（実装指示・完了承認・正本更新）のうちの1つ目。**（推測）0011 の主語は「旧 PM（Cowork 側の Claude）」であり、それをサブエージェント一般へ広げたのはこのレコードである。裁定が明示したのは完了承認だけである** |
| **最終決定** | **仕様・設計の最終決定者は人間のみ。** 0011 のまま変わらない |

## 理由・設計意図

**「外部か内部か」は、権限を決める軸として役に立たない。** 0011 の当時はたまたま一致していた——
外部AIが上流で、内部の Claude Code が役だった。**いまは一致しない。**別ベンダーのモデルが役として働き、
同じ Anthropic のモデルが上流に立つこともありうる。**線は権限の側に引く。**

**責任の範囲を書き分けるのは、検証役に過剰な期待をかけないためである。**
検証役が通したものが後で壊れたとき、「検証役が悪い」と読むと、次に効く手が「もっと厳しく見ろ」しか
出てこない。**実際に効くのは、軸を足すか、道具を届かせるかである。**
このリポジトリでは、検証役が**読むだけでは出ない指摘**（変異テスト・ログの実測・経路の追跡）を
繰り返し出している（`docs/PUNCHLIST.md` に記録があるものだけでも、POL-178 の変異テスト、POL-180 の経路追跡、POL-185 / POL-191 の検証での発見がある）。**ただし「見落とし」が無くなるわけではない** ——
REQ-CFG-018（MUST）の未達は2度、**後から**見つかっている —— POL-185 は検証で、POL-189 は実装役が割り当ての外で。

**（推測）** 「道具の有無が指摘の質を決めている」という一般化は、上の観察からの再構成である。
**測って比べた結果ではない。**

**完了承認を誰にも与えないのは、`CLAUDE.md`「変更の通し方」の5番目（merge は人間が行う）を
どのモデルでも崩さないためである。**

## 出典と確度

- **事実**: 2026-09-03 のユーザー決定。「外部AIの意見は人間を経由してのみ入るという内容は古い」
  「完了承認の権限は無いことはサブエージェント全般に正しい」
  「検証役は検証に責任を持つのであって、全体的な品質に責任を持つわけではない」。
- **（推測）**: 「0011 の線は『Anthropic の外かどうか』ではなく『リポジトリの外か』で引かれていた」は、
  **引用からの再構成である。** 0011 はその基準を明言していない。「当時はたまたま一致していた」も同じく再構成。
- **（出典は会話）**: 検証役の基盤モデルに Anthropic 以外を使う検討は、**2026-09-03 の利用者の発言**による。
  **リポジトリ内に他の出典は無い**（`docs/PUNCHLIST.md` の POL-192 が同じ裁定を記録しているだけである）。
- **事実**: 0011 の「文脈」は、旧体制を「リポジトリ外の Claude（Cowork 側）が**PM 兼実装担当**として動いていた」「正本がリポジトリの外にある」「外部AIの提案がそのまま正本に**入りうる構造だった**」と記す。**「実装指示」「正本更新」という語が権限として否定されるのは「判断」節の引用ブロック**であり、「実務上の意味」が「**旧 PM（Cowork 側の Claude）は**今後、設計相談と監査のみ。**リポジトリに書き込まない**」と書いている。
