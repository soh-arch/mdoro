# 0003. セッション設計に長い休憩・延長・スキップ・中断を含め、自動遷移は既定オフとする

- **状態**: accepted
- **日付**: 2026-08-24

## 文脈

ポモドーロの最小構成は「25分作業 → 5分休憩」の繰り返しである。しかし実際の作業では、
集中が続いているのに時間で切られる、休憩に入りたくない、開始したが別件が入った、といった事態が起きる。
最小構成のままだと、これらを扱う手段が「アプリを無視する」しかなくなる。

## 判断

セッションモデルに次を含める。

- **長い休憩（`LONG_BREAK`）**: `longBreakInterval` 回の `WORK` 完了ごとに提案する。
- **延長**: `WORK` のみ。休憩には設けない（→ [0010](0010-extension-window.md) で起点と受付条件を確定）。
- **スキップ**: セッションを飛ばす。周回数は加算しない。
- **中断（abort）**: セッションを打ち切る。周回数は加算しない。
- **自動遷移（`autoAdvance`）は既定で無効とする。** `FINISHED` に到達しても自動で次を始めず、
  ユーザーが明示的に次へ進む。有効化はプリセット単位の任意設定とする。

## 理由・設計意図

**逃げ道を用意することと、区切りを曖昧にすることは違う。**

延長・スキップ・中断は、いずれも「ユーザーが意識的に選ぶ」操作である。区切りが来たことは必ず提示され、
それに対してどうするかを人間が決める。周回数を加算しないのは、実際にやっていない作業を実績にしないため。

自動遷移を既定オフにするのは、**区切りで一度立ち止まることがポモドーロ手法の中身**だからである。
自動で次が始まる構成は、タイマーが鳴っても手を止めない運用を許してしまう。
必要な人は有効化できるが、それは猶予（`FINISHED` に留まる時間）を放棄することを意味する、と仕様上明示してある。

休憩に延長を設けないのは、休憩が際限なく伸びるため。逃げ道は `WORK` 側にだけ必要である。

## 影響

- 要件: REQ-TIM-010（既定は自動遷移しない）、REQ-TIM-011（`autoAdvance` は SHOULD）、
  REQ-TIM-040〜046（延長）、REQ-TIM-044（休憩に延長なし）、仕様書 4.3〜4.5
- コード: `TimerEngine.swift`、`StateTransitionMatrix.swift`、`SessionType.swift`
- 派生: 周回数の加算はセッションの**正常完了時のみ**。スキップ・中断では加算しない
- 関連: [0006](0006-single-default-preset.md)（既定プリセットでは `autoAdvance` 無効）

## 出典と確度

- **事実**: REQ-TIM-010 / 011、REQ-TIM-040〜045、REQ-TIM-044、仕様書 4.3 に条文として存在する。
- **推測**: 「逃げ道を用意することと区切りを曖昧にすることは違う」という整理は、
  [0010](0010-extension-window.md) でプロダクトオーナーが示した判断基準を、この判断へ遡って適用した再構成である。
  当時この言葉で議論されたという記録はない。
