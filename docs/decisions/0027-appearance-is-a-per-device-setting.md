# 0027. 外観は端末ごとの設定にする

- **状態**: accepted
- **日付**: 2026-08-28

## 文脈

`appearance`（ライト固定 / ダーク固定 / システム追従）は `AppSettings` に置かれ、
**Mac が正本を持つ共有設定**だった。iPhone はスナップショットで受け取った値に従うだけで、
**iPhone 側に選択 UI が無かった。**

工程11 の実機確認で「iPhone にも選択 UI があったほうがよいのでは」という指摘が出た。
共有のまま UI を足すと、**iPhone で暗くすると Mac も暗くなる。**

## 判断

**外観は端末ごとの設定とする。iPhone の選択は iPhone にだけ効く。**

- iPhone は自分の `appearance` を端末内（`UserDefaults`）に保持する。**Mac へ送らない**
- Mac の `appearance` は従来どおり Mac の設定として残る（9.3）
- iPhone の設定画面に「**この iPhone にのみ適用されます**」と明記する

集中表示ビューは従来どおり、外観設定にかかわらず常にダーク（REQ-COL-030）。

## 理由・設計意図

**「状態の正本は Mac」が守っているのは、タイマーの一貫性である。**
周回数・終了時刻・ログの確定は、二重に判断されると壊れる（[0001](0001-mac-as-single-source-of-truth.md)）。
**画面の明るさは、そのどれでもない。** 手元の端末を暗くしても、セッションの結果は1ビットも変わらない。

**外観は「見ている人の事情」で決まる。** 夜に手元の iPhone だけ暗くしたい、
明るい部屋の Mac は明るいままにしたい、というのは矛盾ではなく、**同時に正しい2つの要求**である。
共有設定にすると、この2つが衝突する。

**iPhone の役割の一つは見た目である**（プロダクトオーナーの判断、2026-08-28）。
集中表示ビュー（8.2）という専用の画面を持ち、REQ-UIX-010 が文字高まで規定しているのは、
**iPhone が「見せる」ための端末**だからである。その端末に見た目の設定を持たせないのは筋が通らない。

**通知音とは逆の結論になっているが、理由は同じである。**
[0020](0020-ios-uses-the-default-notification-sound.md) は音色を Mac 専用にした
（iOS に選ぶ手段が無いため）。どちらも「**その端末で意味を持つかどうか**」で決めている。
そして両方とも、**効く範囲を画面に書く**ことを条件にしている。

## 影響

| 対象 | 内容 |
| :---- | :---- |
| REQ-COL-003 | 3択の提供を**端末ごと**と明記 |
| 9.3 | `appearance` は Mac の設定。iPhone は同名の設定を端末内に持つ |
| iOS 実装 | `ClientModel.appearance`（`UserDefaults`）、`AppearanceSheet`、ツールバーの入口 |
| 通信 | **変更なし。** iPhone は `updateSettings` を送らない |

## 出典と確度

- **事実**: 2026-08-28 のユーザー決定。理由（iPhone の意義の一つは見た目にある）は本人の言による。
- **事実**: 集中表示ビューが常時ダークであることは REQ-COL-030。この判断はそれを変えない。
