# 0026. 意匠の定義を埋める（タイポグラフィ・状態・帯）

- **状態**: accepted
- **日付**: 2026-08-27

## 文脈

工程11 は「両端末の GUI を統一する」ことを目的に置いた。しかし着手して分かったのは、
**8.5 は色しか定めていない**ということだった。統一する基準そのものが無い。

実装の棚卸しでは、次のような状態だった。

- 余白は `spacing: 10` が11箇所、`8` が10箇所、ほかに 2 / 4 / 6 / 12 / 20 / 24。**規則なし**
- 角丸は 8 が8箇所、6 が2箇所
- ボタンは `.borderedProminent` 11箇所、`.bordered` 4箇所、`.link` 4箇所、`.plain`、`.borderless`
- **集中表示ビューだけがトークンからボタンの色を引いていて**、通常画面は OS 任せだった

定義が無いまま「統一」を進めれば、**私の手癖が仕様になる。**

## 判断

### タイポグラフィ（旧 OPEN-002）

**残り時間の数字は SF Rounded・medium・等幅数字。現状を追認して骨格に固定する。**

視距離での可読性を優先する。SF Pro は大きな数字にすると硬く、SF Mono は
ログやターミナルの質感に寄りすぎて、**集中表示ビューの巨大な数字では冷たい。**

**数字以外は意味的スタイル**（`.headline` / `.callout` / `.footnote` 等）のままとし、
pt を直接書かない。Dynamic Type に追従させるため（REQ-UIX-006）。
**例外は Live Activity とメニューバー** — 高さが固定で、字が伸びれば行が落ちる。

### 状態の表し方

**トークンを増やさない。** 押下・選択・無効・フォーカスは、既存トークンの組み合わせで表す。
トークンを1つ足すと 8.5.3 の全コントラスト表と REQ-COL-020 の自動テストに波及する。
**色の保証に触らずに状態を足せる形**にしておく。

### 帯（バナー）

**帯は注意を要する状態にだけ使う。正常な状態を帯にしない。**

接続バナーは3状態すべてで帯を使っていた。**正常時に「問題ありません」と全幅で言う要素が、
画面で2番目に大きい**という状態になっていた。接続済みは点と短いラベルで足りる（REQ-UIX-004）。

これに伴い REQ-COL-011 の条文を書き換える。旧「バナー表現は `warning` に予約する」は、
**目的（セッション種別に帯を使わせない）に照らして広すぎた。** 未接続（Clay）の帯まで禁じてしまう。

### 「統一」の定義

**同じ役割に、同じ色・同じ言葉・同じ情報の並びを与えること。**
**器（コントロール）は各 OS の作法に従う。** Mac を iPhone に似せることではない。

### 無効の理由

**無効にした操作には、無効である理由を画面に示す。**
延長ボタンは受付ウィンドウ（REQ-TIM-046）の外では正しく無効になるが、
**理由がどこにも書かれていない。** 押せないものが黙って置いてあるのは、
このリポジトリが通知で一度踏んだ穴と同じ形である（`CONTEXT.md`「失敗を黙らせない」）。

## 理由・設計意図

**基準が無い状態で「揃える」と、揃った理由が誰にも分からなくなる。**
次に触る人（公開後は他人でもある）が、同じ判断を再現できる形にしておく。

**トークンを増やさない縛りは、コントラスト保証を守るための構造である。**
`-subtle` / `-line` / `-graphic` / `-solid` / `-text` の5役は、それぞれ保証する比率が違う
（8.5.3）。状態のために6役目を作れば、その保証を誰かが新たに測り直さねばならない。

**器を OS に合わせるのは、統一の放棄ではない。**
iPhone のリストと Mac の Form は、それぞれの OS で「同じ意味」を担う部品である。
見た目を一致させると、**どちらの OS でも異物になる。**
