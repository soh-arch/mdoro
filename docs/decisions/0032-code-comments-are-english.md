# 0032. コードコメントは英語、`docs/` は日本語

- **状態**: accepted
- **日付**: 2026-08-28
- **反映**: 未（`CLAUDE.md` は更新済み。コメントの英語化は工程14a）

## 文脈

[0022](0022-english-only-ui.md) は「アプリが生成する文字列は英語」と決めたうえで、
**コードコメント・`docs/`・commit メッセージ**をひとまとめに「内部の作業言語」として日本語に残した。
境界を **「利用者に見えるか」** で引いていた。

公開前の監査の軸を定める過程で、この一行が2つの点で実態と合わないと分かった。

- **commit メッセージはすでに英語で運用されている。** グローバルの `CLAUDE.md`、
  `.claude/agents/implementer.md`、および実際のコミット履歴（直近12件すべて英語）が英語。
  [0022](0022-english-only-ui.md) の表だけが日本語のままだった。
- **コードコメントは「利用者に見えない」が「他者に見えない」ではない。**
  OSS として公開すれば、コードを読むのは作者ではない。issue に貼られるのもコード断片である。

このレコードは [0022](0022-english-only-ui.md) の表のうち**コードコメントと commit メッセージの行だけ**を覆す。
他の行（画面・ログ・診断ログ・外部由来の文字列・利用者の入力）は有効のまま。

## 判断

**境界を「利用者に見えるか」から「誰が読むか」へ引き直す。**

| 対象 | 言語 | 理由 |
| :---- | :---- | :---- |
| `docs/`（`SPEC.md` / `CONTEXT.md` / `DEVELOPMENT.md` / `decisions/`） | **日本語** | **母国語だからこそ書ける正確な意図表現を残す。** 決定の意図は、訳した瞬間に精度が落ちる |
| `CLAUDE.md`（運用規律） | **日本語** | 同上 |
| **コードコメント** | **英語** | **簡潔・明示的で、他者が読みやすい必要がある。** コードを読む人と同じ言語で書く |
| commit メッセージ | **英語** | 既存の運用を追認（Conventional Commits） |
| コード中の識別子・型名・ファイル名 | **英語** | 従来どおり |
| 要件IDの記法 | 変更なし | `// REQ-TIM-035: ...` の形式はそのまま。**後続の説明が英語になる** |

`docs/` を日本語のまま残すのは、翻訳の単位が違うからである。
**ドキュメントは丸ごと読まれ、必要なら丸ごと訳せる。** コメントはコードの隣に散らばっており、
読む人はコードと同時に読む。切り替えの費用を払うのは読む側になる。

## 理由・設計意図

**コメントの読み手が変わった。** [0022](0022-english-only-ui.md) の時点では、コメントの読み手は作者と
このリポジトリの Claude Code だけだった。公開後は、**PR を送る人・fork する人・
バグを追う人**が読む。その人たちに日本語を要求すると、貢献の敷居がドキュメントではなくコードに立つ。

**コメントは英語のほうが短くなる。** 日本語のコメントは説明的になりやすい。
英語で書くと、書ける長さの上限が自然に効く。**簡潔さは規律ではなく構造として得たい。**

**`docs/` は逆である。** 決定の記録に求められるのは簡潔さではなく精度である。
「何を守ろうとしているか」を母国語で書けることの価値は、読み手が減る不利益を上回る。
外部の貢献者が必要とするのは `README.md` と `SECURITY.md`（英語）であって、
`docs/decisions/` の全文ではない。

### 言語を変えることは、分量を増やす許可ではない

グローバル `CLAUDE.md` のコメント規律は**そのまま効く。**

- 自己言及的なコメント・コメントアウトしたコードを残さない
- 節見出し・ファイル冒頭のコメントは構造の装飾として可
- 行末コメントは、**コードの意図が推測不能になるのを防ぐ最小限**のときだけ

英語化のついでに説明を足さない。**訳せないコメントは、消すべきコメントである。**

## 影響

| 対象 | 内容 |
| :---- | :---- |
| [0022](0022-english-only-ui.md) | 表の「コードコメント・`docs/`・commit メッセージ」の行を、本レコードへの参照に差し替える。**レコード自体は accepted のまま**（覆すのは1行） |
| `CLAUDE.md`（プロジェクト） | 冒頭の「コードコメントと `docs/` は日本語」を改める |
| コード | 日本語のコメント **1339行 / 87ファイル**（Core 433 / Core テスト 205 / Mac・iOS 676 / Tools 25。うち行末コメント 21。2026-08-28 実測） |
| `.claude/agents/implementer.md` | 要件IDコメントの例が日本語（`// REQ-TIM-035: FINISHED からの脱出先は常に IDLE`） |
| 仕様書 | **変更なし。** REQ-UIX-038 は「アプリが生成する文字列」を定めており、コメントは対象外。**要件数 242 のまま** |
| 監査の順序 | コメント規律の軸（グローバル `CLAUDE.md` 準拠）は、**英語化の後**に回す。先に回すと同じ箇所を2度触る |

**英語化は一度に全部やらない。** 変更したファイルのコメントをその場で英語にする方式では、
日本語と英語が混在した期間が長く続く。**ファイル単位でまとめて行い、レビューできる粒度に切る**
（`docs/PUNCHLIST.md` で管理する）。

## 出典と確度

- **事実**: 判断は 2026-08-28 のプロダクトオーナーの発言による。
  「母国語だからこその私の正確な意図表現を残すため `docs/` は日本語ですが、
  コードコメントは簡潔で明示的で他者が読みやすい必要があるので、英語表記とします」。
- **事実**: コメント行数・ファイル数は `grep` による実測（`//` で始まる行のうち日本語を含むもの）。
  文字列リテラル内の `//` を含みうるため、実作業量はこれより少ない可能性がある。
- **事実**: commit メッセージが既に英語であることは `git log` の直近12件と、
  グローバル `CLAUDE.md`・`.claude/agents/implementer.md` の記述による。
- **推測**: 「コメントは英語のほうが短くなる」は、簡潔さを構造として得たいという意図からの再構成であり、
  プロダクトオーナーがこの言葉で説明したという記録はない。
