# 0035. 失敗は、届く先を決めてから記録する

- **状態**: accepted
- **日付**: 2026-08-28
- **反映**: 未（仕様書は v2.14、実装は工程14c）

## 文脈

[0034](0034-os-errors-are-recorded-as-codes.md) で失敗の**書き方**を決めた。その実装中に、
**書き方以前に届いていない失敗**が3つ見つかった（公開前の監査 POL-035 / 038 / 039）。

| 経路 | 現状 |
| :---- | :---- |
| **保存状態の読み書き** | `AppModel` の3箇所がすべて `try?`。**壊れていても書けなくても、利用者には何も出ない** |
| **診断ログ自身の書き込み** | 失敗を画面に出しているが、OS の原文のまま（[0034](0034-os-errors-are-recorded-as-codes.md) 違反）。**このコードはログに書けない** — ログが壊れているのだから |
| **iPhone が受け取った拒否** | `ClientModel.lastError` に代入しているが、**どのビューからも読まれていない。** 操作が拒否されても iPhone は何も言わない |

`docs/CONTEXT.md` §2 は「**失敗を黙らせない**」を、実際に踏んだ場所として記録している。
3つとも、その条文が想定していた形の違反である。

## 判断

**失敗には届く先がいる。届き先を決められないものは、記録しても守ったことにならない。**

| 経路 | 届き先 |
| :---- | :---- |
| **保存状態の復元の失敗** | **起動時に1度、画面に示す。** セッションとプリセットが失われたことは、黙っていてよいことではない |
| **保存状態の書き込みの失敗** | **ステータス行に出し続ける**（ログ書き込み失敗と同じ扱い）。消えるまで出す |
| **診断ログ自身の書き込みの失敗** | **設定画面にコードで出す。** 画面にコードを出す唯一の正当な場面である |
| **iPhone が受け取った拒否** | **iPhone が `error.code` から自分の英文を出し、画面に示す。** `message` は診断用とする |

### 診断ログのコードだけは画面に出る

[0034](0034-os-errors-are-recorded-as-codes.md) は「利用者はドメインもコードも読みたくない」と決めた。**ここだけ例外にする。**
診断ログが書けないとき、そのコードの行き先は**ログにはない**。捨てるか、画面に出すかしかない。
設定画面の診断ログの節は、**利用者が既にログのことを考えている場所**である。

### `message` は診断用とし、画面の文言は受け取る側が持つ

プロトコルは既に `error.code` を持つ（10.2）。**Mac が iPhone の画面の文言を決めない。**
両端末の文言が独立して保てるうえ、`message` に人向けの文を入れる義務がなくなる。

## 理由・設計意図

**握り潰しは、失敗しないことと区別がつかない。** `try?` は「失敗してもよい」と書いているように見えて、
実際には「失敗を見なかったことにする」と書いている。保存できていないまま使い続け、
再起動して初めて失われたことに気づく経路が、いま存在する。

**`displayMessage` は既に書かれていて、誰にも読まれていなかった。**
[0034](0034-os-errors-are-recorded-as-codes.md) の実装で `StateStoreError` に3つの英文を用意したが、呼び出し口が `try?` のため
**一度も画面に出ない。** 文言を用意することと、届けることは別の仕事である。

**iPhone の沈黙は、Mac の沈黙より重い。** iPhone は操作端末であり、
押しても何も起きないとき、利用者に分かるのは「壊れている」ことだけである。
拒否されたことが分かれば、少なくとも次の手を選べる。

## 影響

| 対象 | 内容 |
| :---- | :---- |
| 仕様書 第12章 | **REQ-ERR-017 を新設**（状態の保存・復元の失敗）。**要件数 242 → 243** |
| 仕様書 REQ-ERR-010 | 診断ログ自身の書き込み失敗を、設定画面にコードで示すことを追記 |
| 仕様書 REQ-ERR-016 | **受信側が拒否を画面に示すこと**を追記。条文は「返す」までしか定めていなかった |
| 仕様書 10.2 | `error.message` を**診断用**と位置づけ、画面の文言は受け取る側が `code` から引くことを明記 |
| `AppModel` | `try? store.load` / `try? store.save` の3箇所を、失敗を受け取る形へ |
| `DiagnosticLogFile` / `SettingsView` | `String(describing:)` をコードへ（[0034](0034-os-errors-are-recorded-as-codes.md) の適用） |
| `ClientModel` / iOS のビュー | `lastError` を画面に出す。`error.code` から英文を引く |
| `LiveActivityController` | 同じ `String(describing:)` の漏れ（POL-037）を同時に塞ぐ |

## 出典と確度

- **事実**: 判断は 2026-08-28 のプロダクトオーナーの選択（3問それぞれで推奨案を採用）。
- **事実**: `ClientModel.lastError` がどのビューからも読まれていないことは、
  `PomodoroMac/PomodoroiOS/Views` に対する検索で確認した（該当なし）。
- **事実**: `StateStoreError.displayMessage` が到達不能であることは、公開前の監査（POL-028 の検証）が
  呼び出し口を追って報告した内容による。
- **推測**: 「iPhone の沈黙は Mac の沈黙より重い」は判断内容からの再構成であり、
  プロダクトオーナーがこの言葉で説明したという記録はない。
