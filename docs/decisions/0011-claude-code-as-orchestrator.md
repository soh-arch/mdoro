# 0011. Claude Code を唯一の実行オーケストレーターとする

- **状態**: accepted
- **日付**: 2026-08-25

## 文脈

それまでの開発体制では、リポジトリ外の Claude（Cowork 側）が PM 兼実装担当として動いていた。
この体制には次の問題があった。

- **正本がリポジトリの外にある。** 判断の経緯、未決事項、プラットフォーム調査の結果が
  外部の会話コンテキストに保持され、失われると復元できない。
- **検証できない。** Cowork 側の環境に Swift がないため、`swift test` を一度も実行できなかった。
  34テストの成否も、ビルドが通るかも未確認のまま「実装完了」として扱われていた。
- **決定権の所在が曖昧になる。** 外部AIの提案がそのままリポジトリの正本に入りうる構造だった。

## 判断

プロダクトオーナーの文言をそのまま記録する。

> Claude Code をリポジトリ内の唯一の実行オーケストレーターとする。人間だけが仕様・設計の最終決定者である。
> 未決定のドメイン判断を検出した場合、Claude Code は実装を止めて選択肢と影響を報告する。
> 実装後は、独立コンテキストの reviewer と機械的な検証を通す。
> 外部AIは、必要時の設計相談または監査に限定し、実装指示・完了承認・リポジトリ上の正本更新の権限を持たない。
> `docs/decisions/` は基本的に Claude Code が管理責任を持つ。

**実務上の意味**

- 旧 PM（Cowork 側の Claude）は今後、設計相談と監査のみ。**リポジトリに書き込まない。**
- プロダクトオーナーが外部AIに相談した結果は、**プロダクトオーナーの言葉として** Claude Code に伝わる。
  外部AIの意見が直接リポジトリに入ることはない。
- この体制が機能しない場合、プロダクトオーナーの判断で見直す。

## 理由・設計意図

**正本をリポジトリの中に置く。** リポジトリ外のコンテキストに依存する情報があると、
セッションが変わるたびに失われる。判断の記録（`docs/decisions/`）、現在有効な方針（`docs/CONTEXT.md`）、
運用規律（`CLAUDE.md`）をすべて Git 管理下に置くことで、誰が引き継いでも同じ前提から始められる。

**検証できる場所で実装する。** テストを実行できない環境で実装を進めると、
「完了しました」が検証を伴わない報告になる。プロダクトオーナーは**検証を伴わない報告を好まない**。
「完了」に対しては必ず状態確認が入る。テストを回さずに完了と言わないこと。

**決定と実行を分ける。** AI は実装と検証を担い、仕様・設計の決定は人間が担う。
曖昧さを検出したときに推測で埋めるのではなく止めて報告するのは、
推測が積み重なると**誰も決めていない仕様**がコードとして固定されるためである。

**外部AIの意見を人間経由に限定する。** 外部AIに相談すること自体は有用だが、
その結果がリポジトリの正本に直接入ると、決定者が誰か分からなくなる。
人間が咀嚼して自分の言葉として伝える経路に一本化する。

## 影響

- `CLAUDE.md` に「未決事項の扱い」「権限」の2条項を追加
- `docs/decisions/` を新設。旧 `NOTES.md`（プロダクトオーナーの判断と意図の記録）を廃止し、ここへ統合
- `docs/CONTEXT.md` を新設。現在有効な方針・制約・未決事項の要約を置く
- `docs/DEVELOPMENT.md` を新設。`CLAUDE.md` からビルド手順・環境メモ・プロジェクト構成を移送
- `.claude/agents/implementer.md` / `reviewer.md` を新設。reviewer は独立コンテキストで成果物のみを見る
- `HANDOVER.md`（一時ファイル）を削除

## 出典と確度

- **事実**: 「判断」節の引用は `HANDOVER.md` §7 に記録されたプロダクトオーナーの文言をそのまま移送した。
  「実務上の意味」も同 §7 の補足からの移送。
  「文脈」節の検証できていない状態（`swift test` 未実行）は `HANDOVER.md` §1 の記述による。
  検証を伴わない報告を好まないことは同 §2 に記録がある。
- **推測**: 「理由・設計意図」節のうち、正本の所在・決定と実行の分離・外部AI経由の限定についての説明は、
  判断内容からの再構成である。プロダクトオーナーがこの言葉で説明したという記録はない。
