# 0020. iPhone は OS の既定通知音のみとする

- **状態**: accepted
- **日付**: 2026-08-27

## 文脈

[0017](0017-system-notification-sounds.md) は「音源は macOS / iOS のシステムサウンドを流用する」
と定めたが、**iOS 側は成立しないことが工程7の実機確認で判明した**（旧 OPEN-016）。

- iOS に `/System/Library/Sounds` は存在しない（実機ランタイムで確認）
- `UNNotificationSound(named:)` が探すのはアプリバンドルと `Library/Sounds` だけ
- iOS のシステム通知音を名前で指す公開 API は無い（`.default` / `.defaultCritical` / `.defaultRingtone` のみ）

選択肢は2つだった。iPhone は既定音のみとするか、音源をバンドルに同梱するか。

## 判断

**iPhone は OS の既定通知音のみとする。音色の選択は macOS 専用の設定である。**

- 無音（`silent`）の選択は**両端末で有効**とする。鳴らす／鳴らさないの判断は共通である
- **共通設定に見せない。** Mac の設定画面では項目名を「**Mac の通知音**」とする。
  ~~iPhone では「音色の選択は Mac のみ」であることを画面に小さく明記する~~
  → **iPhone には出さない。** [0028](0028-explanations-live-on-the-mac.md) が表示場所の条件を置き換えた（2026-08-28）。
  判断の本体（iPhone は OS 既定音のみ、無音は両端末で有効）は有効のまま

## 理由・設計意図

**リポジトリを公開するため、Apple のシステムサウンドを同梱して再配布できない。**
同梱案を採るなら音源の自作かライセンスの明快な素材の調達が要る。
区切りを知らせる音のために、ライセンス管理の対象をリポジトリへ持ち込む価値はない
（`CONTEXT.md`「設計方針」の**簡潔**と**弁える**）。

**実用上の損失が小さい。** Mac と iPhone は同時に通知を出すので、
利用者は2台ぶんの音を同時に聞く。片方が Glass でもう片方が iOS 既定音でも、
伝わる情報は変わらない。0017 の出発点は「区切りが来たことが分かればよい」だった。

**食い違いを隠さないことが、この判断の条件である。** 1つの設定項目が
片方の端末にしか効かないのは、黙っていれば必ず「壊れている」と受け取られる。
**効かない側の画面にも書く**ことで、仕様として読めるようにする
（`CONTEXT.md`「設計方針」の**透明**）。
