# Decision Record

このディレクトリは、**このプロジェクトで下された設計判断と、その背後にある意図**を1件1ファイルで記録する。

仕様書（`../SPEC.md`）は「何を作るか」を、`CLAUDE.md` は「どう作るか」を定める。
Decision Record は **「なぜそう決めたか」** を残す。

条文だけを読んでも、その条文が**何を守ろうとしているか**は分からない。
背後の意図を知らないまま「もっと便利にできる」と手を入れると、守ろうとしていたものが壊れる。
この記録はそれを防ぐためにある。

## ファイル名

```
NNNN-short-english-slug.md
```

`NNNN` は 0001 からの連番。**判断が下された日付順に採番する。** 欠番は作らない。

## 必須項目

各レコードは次の見出しをこの順で持つ。

| 見出し | 内容 |
| :---- | :---- |
| フロントマター | `状態` / `日付` / `反映`（覆された場合は `一部置換` または `置換先`） |
| `## 文脈` | なぜこの判断が必要になったか。何が問題だったか |
| `## 判断` | 何を決めたか。断定形で書く |
| `## 理由・設計意図` | なぜそう決めたか。**何を守ろうとしているか** |
| `## 影響` | どの要件ID・どのコード・どのドキュメントに及ぶか |
| `## 出典と確度` | この記録が何に基づくか。事実と推測が混ざる場合は分けて書く |

## 反映

**判断を記録しただけでは、まだ何も決まっていない。**
`accepted` の判断は、`docs/SPEC.md` の条文かコードに降りて初めて効力を持つ。
フロントマターの `反映` は、それが済んだかを1行で示す。

| 値 | 意味 |
| :---- | :---- |
| `未` | 条文にもコードにも降りていない。**この状態のまま放置しない** |
| `SPEC v2.x` | 当該版で条文に取り込んだ |
| `コードのみ` | 条文の変更を伴わない判断（運用・体制・ツール） |
| `不要` | 反映先が無い（却下された判断の記録など） |

**改訂履歴（`SPEC.md` の 0.x 節）に書いただけでは反映ではない。**
改訂履歴は変更の記録であって条文ではなく、実装者が引ける場所にない。

既存レコード（0001〜0031）の `反映` は、公開前の監査の軸 G で判定して埋める。

## 状態（ライフサイクル）

```
proposed ──► accepted ──► superseded
    │
    └──► rejected
```

| 状態 | 意味 |
| :---- | :---- |
| `proposed` | 提案済み。**人間の承認待ち。** この状態の判断に基づいて実装してはならない |
| `accepted` | 採用済み。実装の根拠として使ってよい |
| `superseded` | 別のレコードに置き換えられた。`置換先: NNNN` を明記する |
| `rejected` | 検討したが採用しなかった。**削除せず残す。** 同じ提案の再来を防ぐ |

## 変更のルール

- **`accepted` のレコードでも、パスの修正・誤字・リンク切れの修正は自由に行ってよい。**
  記録の正確さを保つための編集は歓迎する。
- **新しいレコードが必要なのは、判断そのものを覆すときだけ。**
  その場合は旧レコードを `superseded` にする。
- **一部だけを覆すときは `一部置換` を使う。** 旧レコードの判断のうち一部（表の1行など）だけが
  覆され、残りが有効なままなら、旧レコードは `accepted` のままにし、
  フロントマターに **`一部置換: NNNN（覆された範囲）`** を書く。本文の該当箇所も新レコードへの
  参照に差し替える。**`superseded` にすると、生きている判断まで死んだように見える。**
  **ただし逐語の引用ブロック（人間の文言をそのまま記録した箇所）は編集しない。** 差し替えの代わりに、
  **引用の外側に注記を置く** —— 引用を書き替えると記録そのものが壊れる。
  逆に、何も書かずに本文だけ書き換えると、`accepted` の全文が有効に見えて誤読される。
- `superseded` にするときは、旧レコードのフロントマターに `置換先` を、
  新レコードの `## 文脈` に「何を覆すか」を書く。
- 状態を `accepted` に進められるのは**人間だけ**である（`CLAUDE.md` 「権限」）。
- レコードの管理責任はこのリポジトリの Claude Code が持つ。**サブエージェントは正本を更新しない**（どのモデルで動いていても同じ。[0041](0041-a-role-answers-for-its-check.md)）。

## 新しい判断が発生したら

実装中に仕様・UX・ドメインルールの判断が必要になった場合、`CLAUDE.md` 「未決事項の扱い」に従って
**実装を止め、選択肢と影響を報告する。** 人間が決めたら、その内容を新しいレコードとして起こす。

未決のまま残っている論点は `docs/CONTEXT.md` の「未決事項」に一覧がある。
