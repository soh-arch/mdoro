# 0037. メニューは、取り返しのつかない状態を伝える最後の場所

- **状態**: accepted
- **日付**: 2026-08-28
- **反映**: SPEC v2.16（実装は工程14c）

## 文脈

[0035](0035-a-failure-needs-somewhere-to-arrive.md) で「失敗には届く先がいる」と決め、復元の失敗をメインウィンドウ上端の帯に出した。
検証で、**その帯が届かない場合がある**ことが分かった（公開前の監査 POL-044）。

Mdoro は**メニューバー常駐**であり、メインウィンドウを閉じたまま使える。
ウィンドウを開かない利用者にとって、帯は「閉じるまで残る」が、**そもそも見られない。**
REQ-ERR-017 の「起動時に1度示す」は形式的には満たすが、実質的に届いていない。

[0029](0029-menu-bar-as-a-control-surface.md) はメニューを**操作面**と位置づけた。**伝達面としては使っていなかった。**

## 判断

**メニューは、ごく小さな通知センターを兼ねる。**

**ただし出してよいのは、取り返しのつかない状態と、緊急性の高い場合に限る。**

| 出す | 出さない |
| :---- | :---- |
| **取り返しがつかない**（状態ファイルを退避した、保存が止まっている、ログが書けないまま溜まっている） | 一時的で自然に解消するもの |
| **緊急性が高い**（放置すると失われるものがある） | 完了・成功の報告 |
| — | 進捗、統計、案内 |

**「限る」を条文に書く。** 書かなければ、次に何でも置けるようになる。
メニューは操作面であり（[0029](0029-menu-bar-as-a-control-surface.md)）、**操作を探しに来た人の前に、読み物を並べない。**

## 理由・設計意図

**常駐アプリでは、ウィンドウは「開かれるもの」であって「開いているもの」ではない。**
メインウィンドウにしか出さない伝達は、**開く習慣のある利用者にしか届かない。**
メニューは、常駐アプリで利用者が必ず通る唯一の場所である。

**通知を選ばなかった理由。** 通知は集中を切る。Mdoro は集中セッションのタイマーであり、
**セッション中に割り込む重さと、伝える内容の重さが釣り合わない。**
メニューなら、利用者が自分の都合で開いたときに読める。

**「限る」がこの判断の本体である。** 通知センターを名乗った時点で、
「これも出したい」が積み上がる圧力が生まれる。**取り返しがつくものは出さない。**
利用者が後から直せることを、いま伝える必要はない。

## 影響

| 対象 | 内容 |
| :---- | :---- |
| 仕様書 REQ-UIX-031 | **メニューに伝達を置いてよい条件を追記**（取り返しのつかない状態・緊急性の高い場合に限る） |
| 仕様書 REQ-ERR-017 | 状態の復元・保存の失敗を**メニューにも出す**ことを追記 |
| `MenuBarViews` | 伝達の区画を持つ。**操作の上に読み物を積まない**（[0029](0029-menu-bar-as-a-control-surface.md) の階層を崩さない） |
| 要件数 | **243 のまま。** 既存条文への追記のみ |

**メニューバーの印には載せない。** [0031](0031-the-menu-bar-mark-shows-the-session.md) は「印はセッションの実行状態を示し、
接続状態を載せることを禁じた」。**印は状態の表示であって、伝達の場所ではない。**

## 出典と確度

- **事実**: 判断は 2026-08-28 のプロダクトオーナーの発言による。
  「緊急的なメッセージは伝えるべきメッセージがある場合メニュー内に表示させます。
  ごく小さな通知センターも兼ねると考えましょう。ただし、取り返しのつかない状態である場合や
  緊急性の高い場合に限りましょう。」
- **事実**: 帯が届かない場合があることは、公開前の監査（POL-044）が報告した。
- **推測**: 「常駐アプリでは、ウィンドウは開かれるものであって開いているものではない」という言い方は
  判断内容からの再構成であり、プロダクトオーナーがこの言葉で説明したという記録はない。
