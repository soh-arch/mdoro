# 0028. 説明は Mac に置き、iPhone の画面は空けておく

- **状態**: accepted
- **日付**: 2026-08-28

## 文脈

工程11 で iPhone の通常画面に2つの説明を足した。

- 「iPhone uses the iOS default sound. The choice of tone is Mac only.」（[0020](0020-ios-uses-the-default-notification-sound.md)）
- 「Extending opens in the last 5 minutes」（REQ-UIX-045）

どちらも**正しいことを書いている。** しかし実機で見ると、**画面が文字で詰まって見える。**
iPhone の通常画面は、残り時間・操作・タスク一覧が同時に載る**一等地**である。

## 判断

**説明は Mac の設定画面に置く。iPhone には置かない。**

| 対象 | 置き場所 |
| :---- | :---- |
| 通知音が Mac 専用であること | **Mac の設定画面のみ**（0020 の「両端末に明示」を改める） |
| 延長の受付ウィンドウ | **Mac のメインウィンドウのみ**（REQ-UIX-045 を macOS に限る） |
| 読み上げ（VoiceOver） | **両端末で残す。** 画面から消しても、意味は消さない |

## 理由・設計意図

**役割が違う。** Mac は設定と説明の場所であり、iPhone は**見て・押す**ための端末である
（[0001](0001-mac-as-single-source-of-truth.md) の役割分担の延長）。
設定を変えられない端末に、設定の説明だけを置いても行き場がない。

**この利用者は md でタスクを管理する層である**（[0021](0021-published-as-oss-named-mdoro.md)）。
一度読めば分かることを、毎回の画面に常駐させる必要はない。
**簡潔さは、正しさの次に来る要求ではなく、この製品の要求そのものである。**

**「黙らせない」原則とは衝突しない。** あれは**失敗を隠すな**という原則である
（`CONTEXT.md`「失敗を黙らせない」）。今回消したのは失敗の報告ではなく、**仕様の説明**である。
接続が切れた、ログが書けない、通知が許可されていない — **これらは引き続き両端末に出す。**

## 影響

| 対象 | 内容 |
| :---- | :---- |
| REQ-NTF-006 | 「両端末の画面に明示」→ **Mac の設定画面に明示**。0020 のこの部分を置き換える |
| REQ-UIX-045 | 無効の理由の表示を **macOS に限る**。iPhone は読み上げラベルで補う |
| 0020 | 判断の本体（iPhone は OS 既定音のみ）は**そのまま有効**。表示場所の条件だけを本記録が置き換える |
| 実装 | `MainScreen` から2つの注記を削除 |

## 出典と確度

- **事実**: 2026-08-28 のユーザー決定。理由（文字が多く詰まって見える、Mac で説明すれば済む）は本人の言による。
- **判断**: 読み上げラベルを残すことは私が決めた。画面から消すことと、
  スクリーンリーダーから消すことは別である。
