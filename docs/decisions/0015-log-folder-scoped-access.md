# 0015. 実績ログの出力先はフォルダを選ばせ、ファイル名は設定で持つ

- **状態**: accepted
- **日付**: 2026-08-26

## 文脈

工程4の Mac アプリを実機で動かしたところ、**セッションを1件もログに記録できなかった。**

```
You don't have permission to save the file ".PomodoroLog.md.<uuid>.tmp"
in the folder "pomodoro-test".
```

3つの制約が同時に成立しない状態だった。

- **REQ-LOG-004**（MUST）: 書き込みは原子的に行う（一時ファイルへ書き出し後に `rename`）
- **REQ-PLT-004**（MUST）: 一時ファイルは**ログファイルと同一ディレクトリ**に置く。
  サンドボックス外を跨ぐ `rename` は失敗する
- **サンドボックス**: ファイル単位のセキュリティスコープ付きブックマークは、
  そのファイルへのアクセスしか許可しない。**同じフォルダに別名のファイルを作ることはできない**

当初はファイル選択パネルでログファイル自体を選ばせていた（`NSSavePanel`）。
この方式では、原子的書き込みに必要な一時ファイルを作れない。

## 判断

**実績ログの出力先は「フォルダ」を選ばせ、ファイル名は設定項目として持つ。**

- 設定画面ではフォルダ選択パネル（`NSOpenPanel` / `canChooseDirectories`）を使う。
- 保持するブックマークは**フォルダ**に対するもの。書き込みのたびにフォルダのスコープを開き、
  その中でログ本体と一時ファイルを扱う。
- 9.3 の `logFilePath` を `logFolderPath` + `logFileName`（既定 `PomodoroLog.md`）に分割する。
  従来の `logFilePath` は両者から組み立てる導出値として残す。
- `Task.md` 側は**読むだけ**なので、ファイル単位のブックマークのままとする。
  読み取り専用（`securityScopeAllowOnlyReadAccess`）を維持できるほうが重要である（[0002](0002-task-md-read-only.md)）。

## 理由・設計意図

**原子性を捨てる選択肢は採らない。** その場書き換えにすれば許可の問題は消えるが、
書き込み中のクラッシュや電源断でユーザーのログファイルが壊れる。
アプリの外にあるユーザーの資産を壊さないことが第一原則であり（[0002](0002-task-md-read-only.md)）、
権限の都合でそれを緩めるのは順序が逆である。

**フォルダを選ばせるのは、許可の粒度を実際に必要なものへ合わせる操作である。**
このアプリは「そのフォルダの中で読み書きする」必要があり、それを正直に要求する。
ファイルを選ばせておいて裏でフォルダ権限を要求するより、何を許可したかがユーザーに分かる。

副次的に、**REQ-LOG-002 の「ファイルが存在しない場合は新規作成する」も自然に満たせる。**
ファイル選択パネルはまだ存在しないファイルを選べず、
`URL.bookmarkData` も存在しないパスに対しては失敗する。フォルダ許可があれば、
初回書き込み時にそのまま作成できる。

## 影響

- 要件: REQ-LOG-004（出典を追記）、9.3 の `logFilePath` → `logFolderPath` + `logFileName`、
  REQ-LOG-001（既定名はファイル名設定の既定値として残る）
- あわせて **REQ-LOG-005 に「キューを永続化すること」を追記**した。
  確定時に `committedAt` が立つため（REQ-LOG-019）、未書き込みのキューをプロセス終了で失うと、
  そのセッションの記録は**二度と書かれない**。実機検証中に実際に1件失った
- コード: `AppSettings`、`VaultBookmarks.logFolder`、`AppModel.setLogFolder`、
  `SettingsView` のフォルダ選択、`PersistedState.pendingLogEntries`
- 仕様書 v2.6.1 の 0.9 節に記録

## 出典と確度

- **事実**: 権限エラーは実機（サンドボックス下の Mac アプリ）で再現・確認したもの。
  フォルダ方式に変更後、`~/Desktop/pomodoro-test/PomodoroLog.md` へ2セッション分が
  正しく追記されることを確認した。判断はプロダクトオーナーによる選択（2026-08-26）。
- **推測**: なし。
