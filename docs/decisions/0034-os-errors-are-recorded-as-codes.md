# 0034. OS のエラーは、原文ではなくコードで記録する

- **状態**: accepted
- **日付**: 2026-08-28
- **反映**: 未（工程14c で実装、仕様書は v2.13）

## 文脈

ログの書き込みと状態の永続化が失敗したとき、`LogWriteError` / `FileStateStore` の各ケースは
**OS が返した `error.localizedDescription` を payload に持ち**、それを `String(describing:)` した
文字列が2箇所へ出ていた。

```
画面（MainWindowView）:  writeFailed("ファイル…を開けませんでした。")
診断ログ（AppModel）:     why=writeFailed("ファイル…を開けませんでした。")
```

問題が3つ重なっていた。

- **日本語が出る。** `NSCocoaErrorDomain` の `localizedDescription` は Foundation 自身の
  ローカライズから引かれるため、**アプリの対応言語が英語だけでも、日本語環境では日本語が返る**（REQ-UIX-038 違反）
- **人間向けの文ですらない。** `writeFailed("…")` という enum の生の表記が画面に出ていた
- **`localizedDescription` はファイル名を含むことが多い。**
  [0018](0018-diagnostic-log-policy.md) が「パス・ファイル名を書かない」と決めた `why` フィールドに、
  **経路として抜けが空いていた**

`docs/CONTEXT.md` §2「失敗を黙らせない」を守るために出していたものが、守り方を間違えていた。
公開前の監査（POL-028）で検出した。

## 判断

**画面には、ケースごとの固定した英文を出す。診断ログには、OS のエラードメインとコードを載せる。
`localizedDescription` は保持しない。**

| 出力先 | 内容 | 例 |
| :---- | :---- | :---- |
| **画面** | ケースごとの英文。**利用者が次に何をすればよいかが読める文にする** | `Could not write the session log.` |
| **診断ログ** | **ドメインとコード** | `why=writeFailed(NSCocoaErrorDomain:513)` |
| `localizedDescription` | **保持しない。** 画面にも診断ログにも出さない | — |

エラー型の payload は、文字列ではなく**ドメインとコードの組**を持つ。

### 自前のエラーにもドメインを与える

すべてのエラーが `NSError` 由来ではない。ファイルアクセスの失敗は `NSCocoaErrorDomain` を持つが、
**こちらが自分で投げるもの**（`invalidFilePath` / `wouldModifyExistingLines` / `corrupted` /
`unsupportedSchemaVersion`）にはドメインが無い。

**「ドメインとコード」を名乗る以上、自前のエラーも同じ形で出す。**
診断ログの読み手から見て、OS 由来と自前の区別が**表記の違いとして現れないこと**が要件である。
`Mdoro` をドメイン名とし、ケースごとに固定のコードを振る（`why=writeFailed(Mdoro:1)`）。
`NSError` に寄せるか自前の列挙を作るかは実装の裁量とする。

## 理由・設計意図

**コードは言語に依存しない。** 診断ログの読者は「issue に貼られたログを読む初対面の第三者」である
（[0018](0018-diagnostic-log-policy.md)）。`NSCocoaErrorDomain:513` は誰の環境でも同じ文字列で、
検索すれば意味が出る。日本語の原文は、報告者の環境でしか読めないうえ、**貼られた時点で
読み手を選ぶ。**

**原因の粒度を落とさない。** 種別だけ（`writeFailed`）に丸めると、権限なのか容量なのか
ファイル不在なのかが分からず、issue での往復が増える。[0018](0018-diagnostic-log-policy.md) の
「往復を減らすものを最初から載せる」に反する。**コードは、粒度を保ったまま言語を捨てられる
唯一の表現である。**

**パス漏れの経路が構造的に閉じる。** 伏字処理を足すのではなく、**パスを含みうる文字列を
最初から持たない。** [0018](0018-diagnostic-log-policy.md) は「伏字処理を持たないことが、この判断の要点である」と
述べている。同じ形をここでも採る。

**画面は別の要求に応える。** 利用者はドメインもコードも読みたくない。読みたいのは
「何が起きて、次に何をすればよいか」である。**診断ログと画面で同じ文字列を使おうとしたことが、
そもそもの誤りだった。**

## 影響

| 対象 | 内容 |
| :---- | :---- |
| `LogWriteError` | `readFailed(String)` / `writeFailed(String)` の payload を、ドメインとコードの組へ変更する |
| `FileStateStore` のエラー | 同上 |
| `AppModel` | `lastLogError` に `String(describing:)` を入れない。ケースごとの英文を引く |
| `MainWindowView` / `PresetEditorView` / `PairingView` | 画面へ出す文言をケースから引く |
| 診断ログ | `why` の値をドメインとコードにする（[0018](0018-diagnostic-log-policy.md) の伏字方針と整合） |
| 仕様書 | **REQ-ERR-010 に、OS 由来のエラーはドメインとコードで記録し、原文を保持しないことを追記**（v2.13） |
| `LogWriteError` のテスト | **`Equatable` であり、テストが値を比較している**（7箇所）。payload が変われば落ちる。**落ちたテストを期待値の差し替えで通さない。** 新しい payload が何を保証するのかをテストで表現し直す |
| 要件数 | **242 のまま。** 既存条文への追記のみ |

**エラーの文言そのものは条文に書かない。** v2.11 で19条文から exact 文言を外した方針に従う
（例外4件には当たらない。ここで守りたいのは「原文を保持しない」ことであって、特定の文面ではない）。

## 出典と確度

- **事実**: 判断は 2026-08-28 のプロダクトオーナーの選択（提示した3案のうち「画面は英文、ログはコード」を採用）。
- **事実**: REQ-ERR-010 は既に「利用者由来の文字列（…ファイルパス…）を記録してはならない」と
  定めている。`localizedDescription` はファイル名を含むことが多く、**この判断は新しい制約ではなく、
  既に破られていた条文を守るための手当てである。**
- **事実（2026-08-28 に確認）**: **`why` へのパス混入は疑いではなく実在した。**
  実装時にパーミッションを外したディレクトリへ実際に書きに行ったところ、
  `String(describing:)` の出力に **`NSFilePath=/var/folders/.../MdoroLog.md` が絶対パスのまま**含まれ、
  `localizedDescription` もファイル名を含んでいた。REQ-ERR-010 の「ファイルパスを記録してはならない」に
  対する違反が、経路として成立していた。
- **未確認**: **日本語が返ることは再現していない。** 確認したマシンの Foundation は英語を返した
  （ただし `don't` に U+2019 を含み、ASCII ではない）。日本語環境での再現は行っていない。
  **原文を保持しない判断は、パス混入の一点だけでも成立する。**
- **推測**: 「診断ログと画面で同じ文字列を使おうとしたことがそもそもの誤り」という整理は、
  判断内容からの再構成であり、プロダクトオーナーがこの言葉で説明したという記録はない。
