# 0019. 通知音の試聴は、実際の通知を1件送って行う

- **状態**: accepted
- **日付**: 2026-08-27

## 文脈

[0017](0017-system-notification-sounds.md) は「設定画面で選択した音を試聴できるようにする。
ただし `default` は OS が持つ音でファイルとして指せないため試聴の対象外とする」と定めた。
実装は `NSSound` で音源ファイルを直接鳴らし、既定音のボタンは無効化していた。

2026-08-27、実機で **「Mac だけ通知音が鳴らない」** が報告された。原因は音源ではなく、
**通知が1件も配信されていなかったこと**にある（`willPresent` の不在と、
署名の無いビルドで `requestAuthorization` が失敗し `notDetermined` のままだったこと）。

**試聴は音源を直接鳴らすため、通知経路をまったく通らない。**
「試聴では鳴るのに本番では鳴らない」が成立してしまい、切り分けを助けるどころか妨げた。
既定音が試聴できないことが、最初に気づく入口を塞いでもいた。

## 判断

**試聴のボタンは、選択中の設定のまま通知を1件送る。**

- 対象は全選択肢。**既定音も無音も送れる**（無音は音の鳴らない通知が届く、が正しい挙動）
- `NSSound` による直接再生と `NotificationSound.isPreviewable` は廃止する
- 名称を「試聴」から「テスト通知」に改める

0017 の音源の対応表（Glass / Submarine / Pop）はそのまま有効である。
**本レコードが覆すのは 0017 の「既定は試聴の対象外とする」一文だけである。**

## 理由・設計意図

**本番と違う経路で確かめられるものは、確かめたことにならない。**
試聴が通知を通っていれば、通知が死んでいることはボタン1回で分かった。

**特別扱いが消えて、実装が簡潔になる。** `isPreviewable` の分岐も、
無効化されたボタンとその説明も要らなくなる。「押せるが鳴らないかもしれない」ではなく
「押せば、本番で起きることが起きる」に揃う。

**副作用（通知センターに履歴が残る）は受け入れる。** テストを送ったことが記録に残るのは、
むしろ透明性の側に立つ。

## 影響

- 要件: REQ-NTF-006 の「試聴」を「実際の通知による確認」に改める
- コード: `PomodoroCore/Preset.swift`（`isPreviewable` 削除）、
  `PomodoroMac/Services/NotificationScheduler.swift`（`deliverSoundTest`）、
  `Views/PresetEditorView.swift`
- [0017](0017-system-notification-sounds.md) の該当箇所に本レコードへの参照を追記。
  0017 全体は accepted のまま

## 出典と確度

- **事実**: 「テスト通知を1件送る方式にする」はプロダクトオーナーの決定（2026-08-27）。
  試聴が通知経路を通っていなかったことは実装とログで確認した。
- **推測**: 無音も送れるようにする点、名称変更は Claude Code の判断である。
