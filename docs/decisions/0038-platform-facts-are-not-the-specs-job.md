# 0038. プラットフォームの事実は、仕様書の役割ではない

- **状態**: accepted
- **日付**: 2026-08-29
- **反映**: SPEC v2.18 / `docs/PLATFORM.md` 新設 / `CONTEXT.md` §3 を移送

## 文脈

REQ-UIX-027（MUST）は、こう書いていた。

> Live Activity の配色は 8.5 のトークンをそのまま適用せず、**背景が利用者の壁紙であることを
> 前提に、`--text` / `--bg` の固定値と半透明素材で組むこと。**

**この「背景が利用者の壁紙である」は誤りだった。** ロック画面の Live Activity は
システムのウィジェットコンテナの中に描かれ、既定背景はライトモードで白、ダークモードで黒である
（`PLATFORM.md`「Live Activity」。ActivityKit の一次情報で確認、2026-08-29）。

条文はさらに「コントラスト保証はロック画面上では成立しない」と断じていたが、
**成立しなくなるのはカスタム背景色を敷いたときと Always-On の輝度低下時の2つだけ**である。

**この条文は改訂履歴に一度も現れない。** カラーシステムを設計した頃に書かれ、
Live Activity の実装が2回書き直された後も、一度も突き合わされていない。

同じ理由から引かれた REQ-COL-022（メニューバー）は「色を使わない」という別の答えに落ち着いている。
**同じ問題に2つの答えがあり、片方は検証されていなかった。**

`CONTEXT.md` §3 は「**一次情報で確認済み。再調査しない**」と宣言していたが、
**9項目のうち出典が残っているのは1つだけだった。** 疑うことを禁じる規律だけが効いていた。

## 判断

**プラットフォームの事実を、仕様書にも `CONTEXT.md` にも書かない。**

| 文書 | 書くもの |
| :---- | :---- |
| `SPEC.md` | **Mdoro が何をするか。** 外部の事実を主張しない。必要なら `PLATFORM.md` を参照する |
| `PLATFORM.md`（新設） | **Apple がどう振る舞うかの索引。** 1項目ごとに**調査・確度・確認日・対象バージョン** |
| `docs/platform/`（新設） | **調査そのもの。** 問い・引用・確度・確かめられなかったこと。1件1ファイル、**後から書き換えない** |
| `CONTEXT.md` | **いま何をしているか。** 現在有効な方針と作業状態 |

**確度が `未検証` の項目を根拠に条文を書かない。** 書くなら先に確かめる。

**「再調査しない」の意味を狭める。** 出典と確度が付いた項目についてのみ有効とし、
**バージョンが上がったら確かめ直す。**「永久に正しい」という意味ではない。
疑うときは、**要約ではなく調査のほうを当たる。**

### 調査を、要約と別に残す

**事実だけを要約して置くと、要約した人の手が入った時点で、調査そのものを検証できなくなる。**

条文が実態と食い違ったとき、原因は3つありうる。**調査が不適切だった／調査は正しいが条文が
正しく参照していない／条文の書き方が悪い。** 調査が残っていなければ、この3つを切り分けられない。
1と2を取り違えれば、**正しい調査を疑って調べ直すか、誤った事実の上に条文を書き直す**ことになる。

**公開後は、これを読むのが作者以外になる。**「なぜこの要件がこう書かれているのか」を追える形に
しておくことが、外から見た誠実さでもある。工程12 以降に大規模な改修が必要になった原因は、
**何を事実とみなして設計したのかが追えなかったこと**にある。

調査は `platform-researcher`（`.claude/agents/platform-researcher.md`）が行う。
**一次情報に当たり、確度を3区分（文書化 / 実測 / 不明）で分け、推測で埋めない。**

### 参照が付いているなら、事実が載っていてよい（2026-08-29 追記）

**禁じているのは「事実を書くこと」ではなく、「どこから来た事実か追えなくなること」である。**
参照が付いていれば追える。**参照の無い断定だけを禁じる。**

コードのコメントにもこれを適用する。**コメントは原則として「条文が何を要求しているか」を述べ、
事実は `docs/PLATFORM.md` に委ねる。ただし、事実そのものを1行書いたほうが誤解を防げる場合は、
参照を付けたうえで書いてよい。**

実例（POL-085・[PR #19](https://github.com/soh-arch/mdoro/pull/19)）:

```swift
// Reaches the system's dismiss button, not the view above (docs/PLATFORM.md).
.activitySystemActionForegroundColor(.primary)
```

**`activitySystemActionForegroundColor` という API 名は「本体の前景色」と読める。**
実際に決まるのは終了ボタンの文字色だけである（[platform/0001](../platform/0001-live-activity-lock-screen-background.md)）。
**名前が実際の効果と食い違うとき、参照だけを置いても読み手は誤解したまま通り過ぎる。**

**判断したのは人間である**（2026-08-29）。理由を明示したうえでの例外であること自体が、
この記録の趣旨に適う。**理由の書かれていない例外は、次に読む人にとって参照の無い断定と変わらない。**

## 理由・設計意図

**条文が外部の事実を抱えると、事実が変わったときにどの要件が影響を受けるのか読めなくなる。**
REQ-UIX-027 は「壁紙である」という事実と「固定値で組め」という要求を1文に混ぜていた。
前提が崩れた時点で要求も無効になるが、**条文の形からはそれが分からない。**

**間違った事実は、条文の中でいちばん見つかりにくい。** 要件どうしの矛盾はレビューで見つかる。
テストが落ちれば実装の誤りも分かる。**しかし「iOS はこうなっている」という一文は、
誰かが Apple のドキュメントを開くまで誰も疑わない。**

**「再調査しない」は、正しさの保証ではなく、議論の打ち切りである。**
それ自体は有用で、同じ問いに何度も戻らないために要る。
**しかし打ち切ってよいのは、一度きちんと調べたときだけである。**
出典を残さずに打ち切ると、**確かめていないことと確かめ終わったことの区別がつかなくなる。**
