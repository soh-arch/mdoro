# 0002. `Task.md` は読み取り専用とし、実績は `PomodoroLog.md` へ挿入のみ行う

- **状態**: accepted
- **日付**: 2026-08-24

## 文脈

タスクの一覧は Obsidian の `Task.md` から読む。実績は同じ Obsidian 配下の `PomodoroLog.md` に記録する。
これらはユーザーが日常的に手で編集している、**このアプリのものではないファイル**である。
アプリが書き込みを誤れば、アプリの外にあるユーザーの資産が壊れる。

## 判断

- **`Task.md` へは一切書き込まない。** タスクの追加・編集・完了チェックはすべて Obsidian 側の操作とする。
- `Task.md` 用のセキュリティスコープ付きブックマークは `securityScopeAllowOnlyReadAccess` を付けて生成し、
  **OS レベルでも書き込みを不可能にする。**
- 実績ログは `PomodoroLog.md` への**行の挿入のみ**とする。既存行の改変・削除は行わない。
  論理日境界の都合上、挿入位置は必ずしもファイル末尾ではない。
- 書き込みは**同一ディレクトリ内**で `FileManager.replaceItemAt` を使い原子的に行う。

## 理由・設計意図

「書き込まない」をコードの規律だけで担保すると、いつか誰かが破る。
`securityScopeAllowOnlyReadAccess` は、破ろうとしても OS が拒否する状態を作る。
**規律ではなく構造で守る。**

挿入のみに限るのは、ログファイルがユーザーの編集対象でもあるため。既存行を書き換える実装は、
ユーザーが加えたメモやフォーマットを黙って消す。

`/tmp` を跨ぐ rename はサンドボックス下で失敗するため、原子的書き込みは同一ディレクトリ内で行う必要がある。

## 影響

- 要件: REQ-TSK-001、REQ-PLT-003、仕様書 第14章「Obsidian ファイルへの書き込み制限」
- コード: ログ書き込み層（未実装）。`TimerEngine` は `Effect.commitLog` を返すのみでファイル I/O を持たない
- スコープ: `Task.md` の編集機能は**スコープ外**。提案もしない
- 関連: ファイル監視は記述子ではなく親ディレクトリに張る（`docs/CONTEXT.md`）

## 出典と確度

- **事実**: 仕様書 第14章、REQ-TSK-001、REQ-PLT-003 に条文として存在する。
- **推測**: 「規律ではなく構造で守る」という設計意図の言語化は、`securityScopeAllowOnlyReadAccess` を
  わざわざ MUST にしている事実からの再構成である。
