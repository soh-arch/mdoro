# 0021. OSS として公開する。名前は Mdoro

- **状態**: accepted
- **日付**: 2026-08-27
- **一部置換**: [0044](0044-the-support-link-lives-in-one-place.md)（支援リンクの置き場所の行。**iPhone の設定からは消し、Mac の設定と `README.md` にだけ置く**）。**他の判断は有効。**

## 文脈

ここまでは個人利用のツールとして作ってきた。GitHub で OSS として公開することが決まった。

公開は機能追加ではなく**立ち位置の決定**である。名前・対象読者・資金の扱いが決まらないと、
README も UI の文言も、そもそも「何を断るか」も書けない。
未定のまま英語化やデザイン統一に進むと、決まった後で全部書き直すことになる。

## 判断

**GitHub で OSS として公開する。アプリ名は `Mdoro` とする。**

| 項目 | 決定 |
| :---- | :---- |
| 対象読者 | **Markdown でタスクを管理する人**（エンジニア・パワーユーザー・PKM 層） |
| 立ち位置 | クラウドを一切使わず LAN だけで Mac ⇄ iPhone を同期する。md 全般に対応し、特定ツール専用ではない（[0023](0023-markdown-first-not-obsidian-first.md)） |
| 機能 | **増やさない。** 簡潔・透明・弁える。要望があっても第15章（将来拡張）と第14章（制約）を先に読む |
| 広告・課金・計測 | **持たない。** 広告なし、アプリ内課金なし、テレメトリなし |
| 支援 | Buy Me a Coffee のリンクを**ささやかに**置く。~~置き場所は Mac / iPhone の設定画面の About 節に1つだけ~~ → **置き場所は [0044](0044-the-support-link-lives-in-one-place.md) が置き換えた**（Mac の設定と `README.md` のみ。iPhone からは消す） |

**支援リンクの置き方も決めておく。**

- テキストリンクとし、**画像バッジを同梱しない**（外部素材をリポジトリへ持ち込まない。[0020](0020-ios-uses-the-default-notification-sound.md) と同じ理由）
- 開く前に**リンク先の URL を画面に示す**（`CONTEXT.md` 「設計方針」の**透明**）
- 起動時・セッション終了時・通知など、**集中を切る場所には出さない**
- 回数で再表示するプロンプト、「あとで」ボタン、バッジの類を作らない

## 理由・設計意図

**ニッチが薄いから成立する。** 「クラウド一切なし・LAN のみで Mac ⇄ iPhone」と
「特定ツール専業でなく md 全般」の組み合わせは競合が少ない。
広く当てにいくと、この組み合わせの意味が薄れる。

**対象読者を絞るのは、公開後の管理責任を単純に保つため。**
技術者・PKM 層に絞れば、「ソースからビルドする」「md を自分で書く」が前提として通る。
一般利用者まで対象に広げると、配布・サポート・設定の自動化が要求され、
それは仕様の単純さ（本アプリの取り柄）と正面から衝突する。

**名前に "Pomodoro" を入れない。** Pomodoro Technique は Francesco Cirillo の商標として
知られており、アプリ名に据えると公開後に面倒を招きうる。
`Mdoro` は md（Markdown）に由来し、由来を一言で説明できる。
これは法的助言ではなく、**避けられる面倒は避けるという判断**である。

**支援リンクをささやかに留めるのは、本末転倒を避けるため。**
集中を守るためのアプリが集中を中断させて寄付を募るなら、
そのアプリは自分の主張を信じていないことになる。
利用者が設定画面を開いたときにだけ、そこにある — それで足りる。
