# 0023. Obsidian 専用ではなく、Markdown 一般に対応する

- **状態**: accepted
- **日付**: 2026-08-27

## 文脈

仕様書は Obsidian を前提に書かれている（`SPEC.md` 内に 16 箇所）。
`Task.md` の定義も「Obsidian の保管庫（Vault）内に配置された」で始まる。

しかし公開時の対象読者は「**md でタスク管理している人**」であり、
それが Obsidian の利用者か Logseq の利用者かは問わない（[0021](0021-published-as-oss-named-mdoro.md)）。

**実装はすでに標準 Markdown だけに依存している。** `TaskParser` が見ているのは
チェックボックス記法・見出し・コードフェンスであり、Obsidian 固有なのは
`stableId` の一手段（ブロック ID）と、ログ出力の1オプション（内部リンク記法）だけである。
**縛られているのは実装ではなく文言のほうだった。**

## 判断

**Markdown ファイルを第一級の対象とし、Obsidian は「例のひとつ」として扱う。**

- UI・README・仕様書で、Obsidian を**標準であるかのように書かない**
- Obsidian の利用を**強制も推奨もしない**。「Markdown のタスクファイル」を主語にする
- Obsidian 固有の機能（ブロック ID `^abc123`、内部リンク `[[...]]`）は
  **任意の互換機能として維持する。** 外すのではなく、「Obsidian を使っているなら効く」と位置づける
- 他ツール固有の記法（Logseq の `TODO` / `DOING` マーカー、`id::` プロパティ等）への対応範囲は **OPEN-018**

## 理由・設計意図

**「Obsidian 用」と名乗ると、それ以外の利用者は最初の3行で離れる。**
Logseq・Foam・素の md でタスクを書いている人は、実際には**そのまま使えるのに**、
対象外だと判断してしまう。得るものが無く、失うものだけがある文言だった。

**特定ツールを標準として提示しないのは、弁える設計の一部でもある。**
このアプリは利用者のファイルを読む。読む相手の道具立てに口を出さない。

**互換機能を外さないのは、既存の価値を壊さないため。**
ブロック ID は REQ-TSK-020 の `stableId` として最も安定した手段であり、
「タスク ID の安定性は本システム最大の実装上の難所」（第6章末尾）に対する現時点の最善手である。
Obsidian を標準扱いしないことと、Obsidian の利用者を冷遇することは別である。
