# 0018. 診断ログは公開前提で設計する

- **状態**: accepted
- **日付**: 2026-08-27

## 文脈

REQ-ERR-010（SHOULD）は「診断用ログをローカルに出力し、設定画面から書き出せること」だけを定め、
**保持期間・ローテーション・記録内容を規定していなかった**（旧 OPEN-003）。未実装のまま工程8を終えた。

判断の前提として、このアプリを **GitHub で OSS として公開する**方針が示された（2026-08-27）。
想定利用者は Markdown でタスクを管理するエンジニア・パワーユーザーであり、
**Markdown 連携・簡潔な機能性・安心して使えること**を設計の軸に置く。

この前提はログの設計を根本から変える。**ログの主な読者は「後から見返す開発者」ではなく、
issue に貼られたログを読む初対面の第三者**になる。同時にログは、
**`Task.md` を壊していないことを利用者自身が確認できる唯一の手段**になる。

## 判断

### 1. 利用者由来の文字列を、書き込みの時点で落とす

**タスク名・見出し・本文・パス・サーバー名・端末名・IP アドレスを、ログに一切書かない。**
書き出し時に伏せるのではなく、**ファイルに載せない。**

| 代わりに記録するもの | 形 |
| :---- | :---- |
| タスクの同定 | `stableId` の下4桁（`task=a4f1`） |
| ファイルの同定 | パスの FNV-1a ダイジェスト4桁（`vault=#3f9a`）。同一性の追跡はできるが、内容は復元できない |
| タスク一致の挙動 | 件数と距離のみ（`candidates=3 dist=0`） |

**伏字処理を持たないことが、この判断の要点である。** 書き出しの経路に伏字処理があれば、
そこにバグが入る余地が生まれる。**最初から書かなければ、漏れる経路が存在しない。**

### 2. 保持期間を持たない。2MB × 2世代のローテーションだけを行う

`pomodoro.log` が 2MB に達したら `pomodoro.1.log` へリネームし、新しいファイルを作る。
**古い行を削除する処理は持たない。** 上限は常に 4MB。

### 3. 各ファイルの先頭に環境ヘッダを置く

アプリ版・OS 版・アーキテクチャ・**挙動に効く設定値**（各セッション長、長い休憩の間隔、
通知音、事前通知の構成）を固定で出す。パス・ファイル名は出さない。

### 4. 置き場所は `~/Library/Logs/Pomodoro/`、形式は1行1イベントのプレーンテキスト

追記のみ。排他ロックを持たない。`tail -f` できること。

### 5. Mac のみに持たせる。iPhone 側には持たせない

## 理由・設計意図

**「公開の場に貼られる」を既定とする。** 貼る前に中身を検閲する利用者は少数である。
検閲を前提にした設計は、検閲しなかった一人を裏切る。

**古い行を消す処理を持たないのは、それが一番壊れやすいコードだからである。**
「ファイルを読み、一部を捨て、書き戻す」処理は、`Task.md` に一切書き込まないと決めた
（[0002](0002-task-md-read-only.md)）このアプリが**最も持ちたくない形**をしている。
リネームだけなら、日付のパースも書き戻しも要らない。**壊しようがないものは壊れない。**

**保持期間は結果として決まる。** 通常運用の4MBは数か月ぶんに相当し、
暴走したときは頭打ちになる。「先週おかしかった」と「昨日から大量に出ている」に、
同じ仕掛けで応える。

**ヘッダが無いログは再現できない。** OSS では報告者と修正者が別人になる。
往復を減らすものを最初から載せる。

**iPhone に持たせない理由は、状態の正本が Mac にあるからである**
（[0001](0001-mac-as-single-source-of-truth.md)）。
記録すべき判断はすべて Mac 側で起きる。iPhone 固有の事象（接続・通知・Live Activity）は
画面上の診断表示が担う。ファイルを置けば書き出し導線と共有シートが要り、簡潔さから遠ざかる。

## 影響

- 要件: REQ-ERR-010 に上限・記録内容・ヘッダを追記（要件の新設なし、232要件のまま）
- コード: `PomodoroCore/Diagnostics/`（イベント・整形・伏字・ローテーション・ファイル書き込み）、
  `PomodoroMac/Services/DiagnosticLog.swift`（環境ヘッダの組み立てと呼び出し口）、
  `Views/SettingsView.swift`（書き出しと「記録しないもの」の明示）。
  **ファイル書き込みまで PomodoroCore に置く**のは、`swift test` で実ファイルのローテーションを検証するため
- **設定画面に「タスク名は記録しません」と明記する。** 記録しないと決めたことは、
  決めただけでは伝わらない
- 旧 OPEN-003 を解決済みとする

## 出典と確度

- **事実**: OSS 公開の方針・設計の軸・「タスク名は書かない」「上限4MB」は
  プロダクトオーナーの決定（2026-08-27）。
- **推測**: ローテーション方式・ヘッダ項目・置き場所・iPhone を対象外とする整理は
  Claude Code による提案であり、承認を経ている。
