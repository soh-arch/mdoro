# 0001. 状態の正本を Mac に一本化し、同期は絶対時刻基準とする

- **状態**: accepted
- **日付**: 2026-08-24

## 文脈

Mac と iPhone の2端末でひとつのタイマーを共有する。素朴に実装すると、両端末がそれぞれカウントダウンを持ち、
残り秒数を送り合う構成になる。この構成は次の2つで破綻する。

- **状態の競合**: どちらの端末でも操作できるため、周回数の加算やセッション終了の確定が二重に走る。
  ネットワークの往復遅延や再接続のたびに、古い状態が新しい状態を上書きする（先祖返り）。
- **時刻のずれ**: 残り秒数を同期すると、通信遅延・端末のスリープ・タイマー精度の差がそのまま累積誤差になる。

## 判断

- **タイマー状態の正本は Mac に置く。** 進行判定、周回数の加算、ログ記録の判断、タスクのパース結果、
  設定値の正本はすべて Mac 側にある。
- **iPhone は表示・操作端末とする。** 表示上のカウントダウン補間は行ってよいが、
  **セッションの終了を確定してはならない。** 操作はコマンドとして Mac へ送り、結果を状態として受け取る。
- **同期は残り秒数ではなく終了絶対時刻（`sessionEndAt`）で行う。** 各端末が自分で残り時間を算出する。
- 残り時間の算出には**単調時計**を、`sessionEndAt` の生成とログ表記には**壁時計**を使う。

## 理由・設計意図

正本を1箇所に固定することが、競合と先祖返りを「解決する」のではなく**発生させない**唯一の方法である。
調停ロジックで解こうとすると、再接続・スリープ復帰・同時操作の組み合わせが際限なく増える。

絶対時刻基準にすると、通信が途切れている間も各端末が正しい残り時間を出せる。
これは iPhone のローカル通知を事前スケジュールできる前提でもある（→ [0005](0005-focus-view-instead-of-standby.md)、
`docs/CONTEXT.md` の Apple プラットフォーム確定事項）。バックグラウンドでは WebSocket が切れるため、
`sessionEndAt` を配る設計でなければ iPhone 側に終了を伝える手段が存在しない。

単調時計と壁時計を使い分けるのは、システム時刻の変更やスリープ復帰で残り時間が飛ぶのを防ぐため。
一方でログの表記と `sessionEndAt` は人間が読む時刻でなければならない。
