# 0012. 予告通知の数値の刻みを承認する

- **状態**: accepted
- **日付**: 2026-08-26

## 文脈

[0010](0010-extension-window.md) で予告通知を最大2個のトリガへ拡張した際、
旧 PM（Cowork 側の Claude）が具体的な数値の刻みを決め、そのまま仕様書 REQ-NTF-020 の条文になっていた。

- 残り時間指定（`beforeEnd`）: 1〜15 分を 1 分単位
- 経過割合指定（`atElapsedPercent`）: 50〜95% を 5 刻み

この数値には**人間の確認が取れていなかった。** 条文が MUST / SHOULD として存在するため、
放置すると承認済みのものとして扱われる状態だった（旧 OPEN-009）。

## 判断

**プロダクトオーナーがこの数値を確認し、問題ないと判断した。** REQ-NTF-020 の条文をそのまま採用する。

OPEN-009 は解決済みとして `docs/CONTEXT.md` の未決事項から外す。

## 理由・設計意図

範囲の下限が実装上の保証を作っている。**`beforeEnd` の下限が 1 分であることが、
[0010](0010-extension-window.md) の受付ウィンドウ（終了後1分まで）と対をなしている。**
下限を秒単位まで緩めると、予告と終了が区別できないほど接近しうる。

経過割合を 50% 未満に開かないのは、セッションの前半に「もうすぐ終わる」と伝えても意味がないため。
5 刻みなのは、1% 刻みにしても 25 分セッションでは 15 秒差にしかならず、選択肢がノイズになるため
（[0006](0006-single-default-preset.md) と同じ判断基準）。

## 影響

- 要件: REQ-NTF-020（条文の変更なし。確定のみ）、REQ-NTF-021 / 022 / 023
- 仕様書: v2.6.1 の 0.9 節に確定を記録
- コード: `Packages/PomodoroCore/Sources/PomodoroCore/PreNotification.swift`（新規）、
  `Preset.swift` の `preNotifySeconds` → `preNotifications`
- 未着手: 通知のスケジュール層（Mac / iOS）は未実装。発火時刻の決定のみ `PomodoroCore` にある

## 出典と確度

- **事実**: 承認はプロダクトオーナーの明示的な発言による（2026-08-26）。数値は仕様書 REQ-NTF-020 の条文どおり。
- **推測**: 「理由・設計意図」節は、承認された数値が何と整合しているかを Claude Code が事後に整理したものであり、
  プロダクトオーナーがこの理由で承認したという記録ではない。
