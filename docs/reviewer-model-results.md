## 4. 各モデルが書いたもの

### 4.1 Claude Sonnet 5（対照群）

#### 教材A

**指摘1（重大）——必須段に該当。**

> しかし後段の論法（版が一致する接続内には“将来の相手”というシナリオが原理的に存在しない）は、前段が「未知のフィールド・未知のメッセージ種別」を無視する根拠とした「前方互換性」という前提を、同じ強さで否定する。

そのうえで `type` に未知の値が来る場合を具体例として挙げ、
**「隣接する2つの規範（「無視」と「破棄してカウント」）が、両立しない前提の上に並置されている」**と述べている。

**期待していた指摘は「根拠が証明しすぎている。同じ論法が未知の種別にも及んで前半が空文になる」。**
**言い方は違うが、同じ構造を指している。**

**指摘2（重大）——採点表に無い、正しい指摘。**

「既知のフィールドに載る未知の値」の範囲が未定義であり、
**REQ-CFG-018**（範囲外の設定値に `settingOutOfRange` を返す・MUST）および
**REQ-TSK-036**（存在しない `stableId` に `taskNotFound` を返す・MUST）と衝突する、というもの。
`idleResetHours: 999` と `selectTask` の2つを具体例として挙げている。

**これは、この稿が落ちたあとの裁定が到達した理由そのものである。**
2026-09-02 の裁定（POL-179）は「**分類ではなく順序で決める —— 応答を定めた条文があるならそれに従い、
定めが無い値だけを破棄する**」であった。**対照群は答えを見ずに同じ場所へ着いている。**

**指摘3（中・「疑い」と明記）**: MUST である REQ-PRT-005 が、SHOULD である REQ-ERR-009 の
処理手順（数える・10回で切る）を義務として引き継いでおり、レベルの整合が説明されていない。

**落としたもの**: 採点表の副次「『版を上げずに値を足した』は、どの条文にも Decision Record にも無い前提」
（POL-184）は出ていない。**必須段ではない。**

#### 教材D

**指摘1（重大）——必須段に該当。**

> さらに、`type` が後段の例示に明示的に含まれている以上、冒頭の「未知のメッセージ種別を無視する」という規定は適用される場面が存在しない（自己無効化している）ことになる。

**期待していた指摘は「例示に `type` を入れたことで、前半を取り消している」。**
**「自己無効化」という語で同じものを指している。**

**指摘2（重大）**: 同じ矛盾が REQ-ERR-009 の切断・再接続の挙動にまで波及する。

**指摘3（中）——採点表に無い、正しい指摘。**

条文はメッセージ単位でしか読める／読めないを決めておらず、**解析の不可分性を要求していない。**
したがって、深い階層の未知値を検出する**前に**既知フィールドを状態・画面へ適用する実装は、
条文を字義どおり守ったまま、**条文が防ぎたいとする「相手が言っていないことを画面に出す」結末に到達する。**
末尾の「（背景・非規範）」注記がこの残存リスクを認めているが、**規範側では対処されていない**とも指摘している。

**指摘4（「疑い」と明記）**: 「値の集合が閉じているフィールド」の範囲が条文内で完結していない。
`runState`（4.1）や `notificationSound` / `idKind` / `decision` / `PreNotification.type`（10.3）のように、
**10.2 以外の節で値集合が列挙されているフィールド**が含まれるかどうかが文言から確定できない。

**落としたもの**: 採点表の副次「REQ-CFG-018 との同型の衝突」は、**教材D では出ていない。**
ただし**教材A で同じ衝突を指摘している**（上記の指摘2）。
