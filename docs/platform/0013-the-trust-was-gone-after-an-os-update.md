# 0013 — OS の更新の後、署名の信頼が外れていた（2026-09-05）

**問い**: iPhone を iOS 26.6.1 へ更新した後、実機の Mdoro に何が起きたか。
**Mac を据え置いたまま iPhone だけを上げた**とき、何が壊れ、何が生き残るのか。

**方法**: 所有者による実機での観察。計測コードではなく体験の報告。**1機・1回。**
スクリーンショットもログも残っていない。**文言は逐語では取れていない。**

**対象**: macOS 26.5.1（据え置き）/ **iOS 26.6.1**（iPhone 17。2026-09-04 夜に更新）/ Xcode 26.6

## 答え

**塞いでいたのは、Personal Team 署名の開発者信頼が無い状態である。**
その状態は「アプリが起動しない」「ビルドが通らない」として現れ、
**「信頼せよ」という案内は遅れて出た。****再ビルドでは直らず**、
設定 > 一般 > VPN とデバイス管理でアカウントを信頼し直したときだけ直り、
アプリは起動して**ペアリングは操作なしで復帰した。**

**その信頼を外したのが OS の更新そのものかは、切り分けていない。**
観察されたのは**更新の直後に起きたという時間的な一致**であって、機構ではない。

## 観察された順序

| 時点 | 観察 |
| :---- | :---- |
| 更新直後 | **アプリが起動しない** |
| 続けて再ビルド | **通らない** |
| 数回試し、数分が経った頃 | **「Developer が認証されていない」旨の案内が出た** |
| 設定 > 一般 > VPN とデバイス管理でアカウントを信頼 | — |
| 再ビルド | **通った** |
| 起動後 | **Mac の Mdoro と、何の操作もなしに自動的に接続された** |

**利用者の視点からは「認証が外されただけ」に見えた。**

## 同時に確認できたこと

| 事実 | 確度 |
| :---- | :---- |
| **Xcode 26.6 は iOS 26.6.1 の実機へビルドを降ろせる。** 信頼さえ回復すれば device support は足りている | **実測** |
| **ローカルネットワーク許可のダイアログは出なかった。** 許可は OS の更新をまたいで生存する | **実測** |
| **ペアリングは操作なしで復帰した。** iPhone の Keychain のトークン・Mac 側の `issuedDeviceTokens`・Bonjour による発見の3つが、更新をまたいで同時に成立していた | **実測** |
| **Live Activity のロック画面表示は機能する** | **実測** |
| **セッション終了通知は届く** | **実測** |

## 確度

- **実測**: 上の2つの表の内容。ただしすべて**1機・1回の観察**である
- **不明** — Xcode が出した文言。覚えていない。**ただし「アップデートを挟んだとき以外に見たことがないメッセージ」であり、日常的なビルドエラーではなかった**という証言がある
- **不明** — iOS 側の文言。逐語では残っていない
- **不明** — **「数分」の意味。** 再試行が引き金だったのか、単に時間が経ったのかを切り分けていない
- **不明** — **Mac 側の Mdoro が連続稼働していたか。** 「再起動する理由がなかったので普段どおり起動したままだったはず」という報告だが、
  **所有者自身が「意識して記憶していない」と述べている。** 推定であって観察ではない

## 確かめられなかったこと

**2026-09-18 追記**: このうち「更新の大小で挙動が変わるか」と「Mac 側が更新中ずっと起動していたか」には、
**Mac だけを上げた観察**（[0014](0014-what-a-mac-update-kept-and-what-it-asked-again.md)）で一部答えが出ている。
**下の「ローカルネットワーク許可は更新をまたいで生存する」は iPhone の更新についての実測であり、**
**Mac の更新では成り立たなかった。**

- **信頼が外れた原因。** 更新が引き金だったのか、**更新とは無関係な時間経過による失効がたまたま重なった**のかを
  切り分けていない。**既知の7日失効ではない可能性が高い** —— それなら再ビルドで直るはずで、実際は直らなかった ——
  **が、別の時間経過型の失効を排除できていない。** 切り分けるには次の更新で再現を見るしかない
- 両 OS の**文言の逐語**
- 案内が遅れて出た**原因**
- Mac 側が更新中ずっと起動していたか（上記）
- **有償の Apple Developer Program でも同じか。** 観察は Personal Team のみ
- **更新の大小で挙動が変わるか。** 26.6 → 26.6.1 の1例しかない。メジャー更新は未観察
- **予告通知**（REQ-NTF-007 / 020〜023）。**今回も通しでは観察していない。**
  `docs/CONTEXT.md` の時点から「発火時刻の算出は単体テスト済みだが通しでは未確認」のままである
- ダイナミックアイランド・`staleDate` の陳腐化表示・`LiveActivityIntent` の各表示面
- **iPhone だけが新しい状態での SF Symbols の実機カタログ。** [0006](0006-sf-symbols-catalog-and-availability.md) が
  「カタログは macOS 26.5 と iOS 26.5 で同一」と実測したのは**同一バージョン同士の比較**であり、
  いまはその前提が崩れている。**実機 26.6.1 のカタログは読んでいない**
