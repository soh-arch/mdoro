# 0014 — Mac の更新をまたいで残ったものと、訊き直されたもの（2026-09-18）

**問い**: Mac を macOS 26.5.1 から 26.7 へ更新したとき、更新前に成立していた
Mdoro の持ち物は生き残るか。**iPhone を据え置いたまま Mac だけを上げる。**

[0013](0013-the-trust-was-gone-after-an-os-update.md) の裏返しである。あちらは
**iPhone だけ**を上げて Mac を据え置いた。

**方法**: 所有者による実機での観察。**1機・1回。** 更新前に各項目の状態をスクリーンショットで
記録し、更新後に同じ画面を見て比べた。**スクリーンショットは残っている。**

**対象**: MacBook Air（M5）/ macOS **26.5.1（25F80）→ 26.7（25G229）** /
Xcode **26.6（17F113）据え置き** / iPhone 17 は **iOS 26.6.2 据え置き**

## 観察を成立させるために先にやったこと

**更新の直前に Mdoro を再ビルドして iPhone に入れ直した**（2026-09-18 02:18 JST）。
**Personal Team 署名の7日失効を、この観察から除くためである。** 更新後に iPhone 側で何が
起きても、「7日で切れただけかもしれない」という説明が使えない状態にした。
[0013](0013-the-trust-was-gone-after-an-os-update.md) が最後まで切り分けられなかったのが
そこだった。

**Mac の Mdoro は Cmd-Q で終了してから更新した。** 0013 では「Mac 側が更新中ずっと起動して
いたか」が不明のまま残っていたので、今回は既知にした。

## 答え

**5つ見張って、4つが生き残り、1つが訊き直された。**

訊き直されたのは**ローカルネットワーク許可**である。

## 生き残ったもの

| 事実 | 確度 |
| :---- | :---- |
| **login キーチェーン。** Mdoro の起動でパスワードを訊かれなかった（署名 identity が変わっていない徴候） | **実測** |
| **読み取り専用ブックマーク。** タスクファイルとログフォルダを訊き直されず、`Could not read the task file` も `The session log could not be written` も出なかった | **実測** |
| **通知の許可。** `Allow notifications` が ON、Desktop / Notification Center / Lock Screen の3つともチェックのまま | **実測** |
| **ペアリング。** Mac 側の一覧に `Paired Sep 2, 2026 at 17:24` が残り、**コード入力なしで再接続した** | **実測** |
| **iPhone の開発者信頼。** アプリは起動した。**7日の時計が 0 なので、7日失効ではありえない** —— **Mac だけの更新は iPhone 側の信頼を落とさない** | **実測** |
| **`xcode-select -p`** は `/Applications/Xcode.app/Contents/Developer` のまま。**Xcode 26.6 のまま起動し、ライセンス同意も要求されなかった** | **実測** |
| **永続化した状態。** ループ数 `3 / 4` が再起動をまたいで残っていた | **実測** |
| **`POL-164` の常設案内。** Connection タブの「macOS does not tell Mdoro when that permission is off」の文言は macOS 26.7 でも出ている | **実測** |

**Xcode 26.6 が 26.7 で動くのは偶然ではない。** Apple のサポート表は Xcode 26.6 の対象を
**「macOS Tahoe 26.2 – macOS Tahoe 26.x」**としており、26.7 はその内側である
（<https://developer.apple.com/xcode/system-requirements>、2026-09-17 参照）。

## 生き残らなかったもの —— ローカルネットワーク許可

**再起動の後、約10個のアプリについて許可のダイアログが連続で出た。**
そして**答えた内容で以前の状態が置き換わった。**

| アプリ | 更新前 | 更新後 |
| :---- | :---- | :---- |
| `Hermes.app` | ON | **OFF** |
| `ChatGPT.app` | ON | **OFF** |
| `Google Chrome.app`（複数行） | OFF | **ON** |
| `Comet.app` | OFF | **ON** |
| `iTerm.app` / `Cursor.app` / `Slack.app` / `Spark Desktop.app` | 一覧に無い | **新規に出現** |

**`MdoroMac.app` は1行のままで、2行に増えていない。** 同じアプリでも署名が違えば別の行として
並ぶ（`Google Chrome.app` が5行あるのがその例である）ため、**行が増えなかったことは署名の
同一性が保たれたことを示す。** 上のキーチェーンの結果と一致する。

**所有者はダイアログの流れの中で Mdoro を一旦 OFF にした。** その後 ON に戻し、Mdoro を
終了して起動し直している。**拒否の状態は意図して作ったものではないが、トグルで作れる** ——
Apple が「戻せない」と述べているのは**未決定の状態**であって、拒否ではない
（[0005](0005-local-network-privacy-and-platform-settings.md) / FB14944392）。

## [0013](0013-the-trust-was-gone-after-an-os-update.md) との食い違い

[0013](0013-the-trust-was-gone-after-an-os-update.md) は
**「ローカルネットワーク許可は OS の更新をまたいで生存する。再許可のダイアログは出なかった」**
を**実測**として記録している。

**矛盾ではない。あれは iPhone の更新の観察である。**

**片側で測った結果を、もう片側に一般化できない。** それがこの観察の要点である。

## 確かめられなかったこと

- **許可が訊き直された機構。** 記録が作り直されたのか、アプリごとに再要求されただけなのかを
  切り分けていない。**観察できたのはダイアログが出たことと、前後で状態が違うことだけである**
- **Mdoro 以外のアプリの前後を網羅していない。** 上の表はスクリーンショットに写っていた範囲である
- **メジャー更新（26 → 27）では未観察。** 今回はマイナー更新であり、
  [0013](0013-the-trust-was-gone-after-an-os-update.md) が残した「メジャー更新は未観察」は**まだ埋まっていない**
- **更新後に再ビルドが実機へ降りるかは試していない。** 0013 でいちばん目立った症状
  （**再ビルドも通らない**）の裏返しにあたるが、この観察では確かめていない
- **Mac の Mdoro が、更新の再起動後に自分で起動した。** ログイン項目なのか
  「再ログイン時にウインドウを再度開く」なのかを切り分けていない
- **有償の Apple Developer Program でも同じか。** 観察は Personal Team のみ

## この観察の途中で見つかった、別の2件

どちらも**更新が壊したものではなく、更新したから見えたもの**である。起票済み。

- **POL-296** —— 4G から Wi-Fi へ移しても繋ぎ直さず、両端末のアプリを終了・起動して初めて
  繋がった。所有者は「前からよく見かける」と述べている
- **POL-298** —— 診断ログのヘッダが、ファイルを開いた日（2026-08-27）の OS 版と設定を
  書き続けていた。**版が動かない限り、嘘は嘘に見えない**

## 影響を受ける記述

- [0013](0013-the-trust-was-gone-after-an-os-update.md) の「確かめられなかったこと」のうち、
  **「Mac 側が更新中ずっと起動していたか」は今回は既知である**（終了させてから更新した）
- [0013](0013-the-trust-was-gone-after-an-os-update.md) の対象は iOS 26.6.1 だが、
  **同じ iPhone はその後 26.6.2 に上がっている。** あの観察の記録としては正しく、
  **現況の記述として読まないこと**
