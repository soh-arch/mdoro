# platform — 調査の記録

このディレクトリは、**Apple プラットフォームについて何を調べ、何が分かったか**を1件1ファイルで残す。

`PLATFORM.md` は**事実の索引**であり、ここは**その事実がどこから来たか**である。

## なぜ分けるか

事実だけを要約して置くと、**要約した人の手が入った時点で、調査そのものを検証できなくなる。**

条文が実態と食い違ったとき、原因は3つありうる。

1. **調査が不適切だった**
2. **調査は正しいが、条文がそれを正しく参照していない**
3. **条文の書き方が悪い**

**調査が残っていなければ、この3つを切り分けられない。** 1と2を取り違えれば、
正しい調査を疑って調べ直すか、誤った事実の上に条文を書き直すことになる。

**公開後は、これを読むのが作者以外になる。** 「なぜこの要件がこう書かれているのか」を
追える形にしておくことが、外から見た誠実さでもある。

## ファイル名

```
NNNN-short-english-slug.md
```

`NNNN` は 0001 からの連番。**欠番を作らない。** 調査した日付順に採番する。

**後から書き換えない。** 調査は「その時点で何が分かったか」の記録である。
新しい事実が出たら**新しい番号で起こし**、古い記録の冒頭に「NNNN が更新した」と1行足す。

## 必須項目

| 見出し | 内容 |
| :---- | :---- |
| フロントマター | `調査日` / `対象`（OS・SDK のバージョン） / `依頼の理由` |
| `## 問い` | 何を確かめようとしたか。**そのまま書く** |
| `## 答え` | 1〜2文で先に |
| `## 根拠` | URL・文書名・**該当箇所の引用**。WWDC なら年とセッション番号 |
| `## 確度` | `文書化` / `実測` / `二次情報` / `不明` の区分ごとに |
| `## 確かめられなかったこと` | **推測で埋めない** |
| `## 影響を受ける記述` | この調査によって見直しが要る条文・コード・記録 |

## 誰が書くか

`platform-researcher`（`.claude/agents/platform-researcher.md`）が調べ、報告する。
**ファイルとして置くのはオーケストレーターである**（役は `docs/` を編集しない）。

**報告を要約しない。** 確度の区分・引用・確かめられなかったことは、**そのまま残す。**
要約したい欲求が出たら、それは `PLATFORM.md` の側でやる。
