### 問いへの答え

1. **両端に数える主体が存在するか** —— 存在しない。iPhone 側にのみ `BrokenMessageCounter` があり、Mac 側には対応する主体が一切無い。
2. **その部品は共有パッケージに置かれているか** —— 置かれていない。`BrokenMessageCounter` は `MdoroCore` ではなく `MdoroiOS`（アプリ）ターゲットの `MdoroClient.swift` に private に定義されている。REQ-PRT-001「数える部品は両端で共有すること」に反する形。
3. **片方が「黙って捨てるだけ」であるなら、REQ-PRT-005 が MUST として命じている「数えること」は、その端では誰が満たすのか** —— **誰も満たしていない。** Mac 側 (`MdoroServer.swift:224`) は `guard let envelope = try? MessageCoder.decodeClient(data) else { return }` のみで、破損メッセージ1件ごとに無条件で握りつぶすだけであり、カウントする変数・呼び出しがコードベース中のどこにも存在しない（`grep -rn -i "brokenmessage\|broken message" Packages/MdoroCore/Sources` はヒット0件、`grep -rn "Counter" PomodoroMac/PomodoroMac/` もヒット0件）。仕様の REQ-ERR-009 は「Mac は連続10回で接続を切る」ことを求めているが、そのための計数機構自体が存在しないため、Mac は連続何回受けてもこの動作を発火しない。

### 一覧: MUST の動作が他条文（特に SHOULD）に委ねられている箇所

自動抽出（`material-B.md` 全 MUST 行の本文中に現れる別要件IDを、その要件IDのレベルと突き合わせ）した結果、本文中に SHOULD 要件IDを引用している MUST は以下。**委任の強さ**で3分類した。

| 参照元 (MUST) | 参照先 (SHOULD) | 委任の型 | 該当行の要旨 |
|---|---|---|---|
| **REQ-PRT-005**（918行） | **REQ-ERR-009**（1158行） | **全面委任** — 「REQ-ERR-009 の破損メッセージとして扱い、破棄して数えること」。数える主体・回数上限・回線を切る条件は全て ERR-009 側の定義に依存 | 既知フィールド上の未知値の扱い |
| **REQ-UIX-007**（477行） | **REQ-PRS-013**（876行） | **全面委任** — 「1件のみの場合は REQ-PRS-013 に従う」。1プリセット時の挙動を丸ごと SHOULD 条文に譲渡 | プリセット切替 UI の1件時の挙動 |

| REQ-UIX-026（514行） | REQ-UIX-024（512行） | 論拠参照のみ／除外規定 — UIX-024（ボタンを置いてよい、SHOULD）が実装された場合の例外境界を説明するのみで、UIX-026 の禁止自体は自己完結 | Live Activity のネットワークアクセス禁止 |

**「MUST が SHOULD の動作に依存している」条文**として同型のものは、抽出した中では **REQ-UIX-007 → REQ-PRS-013** と **REQ-TSK-035 → REQ-TSK-032** の2件。いずれも「その場合の挙動を丸ごと SHOULD 条文に譲渡する」書き方であり、対象の SHOULD が実装されなければ委任先の挙動が存在しなくなる点で REQ-PRT-005 → REQ-ERR-009 と同型。

（注: この抽出は「本文に他要件IDが明記されている」行のみを機械的に拾ったもの。IDを明示しない暗黙の依存がさらにある可能性は排除できない。）

### 問いへの答え

**「SHOULD である REQ-ERR-009 を実装しない選択をした実装は、MUST である REQ-PRT-005 に適合しているといえるか」**

条文の文言に即して読む限り、**適合しているとは言い切れない**。

- REQ-PRT-005 は MUST として「既知のフィールドに載る未知の値」について「REQ-ERR-009 の破損メッセージとして扱い、**破棄して数えること**」と明記している。「数えること」は ERR-009 側の説明の引用ではなく、PRT-005 自身の条文本文に直接書かれた指示である。
- ERR-009（SHOULD）が定義しているのは「数える」という動作そのものの中身（何をもって1回とし、何回で何をするか、部品を両端で共有すること）である。
- したがって、ERR-009 を実装しない（＝数える部品を作らない）選択をすると、PRT-005 が名指しで要求する「数える」という動作の実体がどこにも存在しなくなる。B-1 で実際に確認した Mac 側の実装（`MdoroServer.swift:224`）がまさにこの状態であり、「握りつぶすだけで数えていない」。
- 一方で、「discard」（既知の別ケースに誤読しない）という PRT-005 のもう一つの核 —— 未知値を別の妥当なケースに解釈しないこと —— はカウンタの有無に関わらず満たせる。この部分だけを見れば PRT-005 の趣旨（前方互換性の誤読防止）は保たれているとも言える。

以上より、**「数えること」を PRT-005 自身の MUST 内容の一部と読むか、ERR-009 側に属する付随的な記述と読むかで結論が割れる**。前者の読みでは Mac 側の現状実装は PRT-005 に不適合、後者の読みでは（discard 部分のみで）適合、という両論がある。条文の文言（「破棄して**数えること**」がPRT-005の行に直接ある）を素直に読む限り、報告者としては前者（不適合）に傾く読みが妥当と考えるが、これは条文解釈に関わる判断であり、採否・裁定はオーケストレーターの役割と理解している。
