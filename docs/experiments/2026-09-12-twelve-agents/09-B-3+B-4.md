**Mac 側（`MdoroServer.swift:224`）とiPhone 側（`MdoroClient.swift:152-176`）でどの分岐に落ちるか**

| # | 出口 | **Mac** の分岐 | **iPhone** の分岐 |
|---|---|---|---|
| 1 | 未知の種別 | `guard let envelope = try? | 2 | 未知のフィールド | 通常の `.hello`/`.command` 等として処理（`handle` の switch、`:226-249`）。余分なフィールドは黙って落ちる | 通常の `switch envelope.body`（`:178〜`）として処理。同様 |
| 3 | 既知フィールドの未知の値 | `decodeClient` が throw → **同じ `try?` に飲み込まれ nil**。**出口1とまったく同じコード行に落ちる**。カウントなし | `do { decoded = try decodeServer(data) } catch { ... brokenMessages.recordBroken() ...; return }`（`:154-170`）。**出口1と明確に区別され、カウントされる** |
| 4 | JSON壊れ | 同上、`try?` に飲み込まれ nil。カウントなし | 同上、`catch` に入りカウントされる |
| 5 | 必須ヘッダ欠落 | 同上、`try?` に飲み込まれ nil。カウントなし | 同上、`catch` に入りカウントされる |

**問いへの答え**

「無視する」出口（1・2）と「破棄して数える」出口（3・4・5）は、**iPhone側のコードでは区別できる**（`do/catch` が throw の有無で二分し、`BrokenMessageCounter.recordBroken()` を呼ぶかどうかが分かれる。`MdoroClient.swift:152-176`）。

しかし **Mac側のコードでは区別できていない。** `MdoroServer.swift:224` の一行 `guard let envelope = try? MessageCoder.decodeClient(data) else { return }` は、出口1（前方互換で無視してよい）と出口3・4・5（REQ-ERR-009 の破損メッセージとして「破棄して数える」べき）を **同一の `nil` に均して同一の `return` に送る。** Mac のコード全体を検索したが、`MdoroServer.swift` に `BrokenMessageCounter` 相当の仕組みは一切存在しない（後述コマンド出力）。

したがって、条文が立てる3分類（未知種別／未知フィールドは無視、既知フィールドの未知の値・破損 JSON・ヘッダ欠落は破棄して数える）は、**Mac側の受信コードでは実施不能である。** 「数える」という第3の出口が Mac には存在せず、REQ-ERR-009 が明記する「Mac は連続10回で接続を切る」という振る舞いも、少なくとも `MdoroServer.swift` 上のこの受信経路には実装が見当たらない。加えて、REQ-ERR-009 の但し書き「数える部品は両端で共有すること（REQ-PRT-001）」も、`BrokenMessageCounter` が `PomodoroiOS/Client/MdoroClient.swift` にのみ定義された private struct であり `MdoroCore` に置かれていない（＝共有されていない）ため、そもそも共有すべき部品がMac側に存在しない状態と符合する。

## B-4: プロトコル版検査の列挙

**作った一覧**

| 側 | 主体（誰が） | 何と比較 | 場所 |
|---|---|---|---|
| `hello` | Mac（`Authenticator.authenticate`） | `hello.protocolVersion` vs `PomodoroProtocol.version`（`PomodoroProtocol.isCompatible`） | `Pairing.swift:121-125` |
| `welcome` | **存在しない** | — | 該当コードなし（後述コマンド） |
| TXT `v`（REQ-COM-003） | **存在しない**（書く側のみ） | — | 書く: `BonjourService.swift:18,33` ／ 読む: `DiscoveredServer.swift:111-118` は `websocketPortKey` と `identityKey` のみ抽出し `versionKey` を読まない |

`isCompatible` の呼び出しは全リポジトリ中この1箇所のみ（コマンド出力は下記）。

**問いへの答え**

**(a) `welcome.protocolVersion` を検査する主体は存在するか → 存在しない。**
`MdoroClient.swift` の `.welcome(payload)` 処理（`:179-185`）は `payload.serverName` / `payload.deviceToken` のみを読み、`payload.protocolVersion` には一切触れない。全リポジトリを `protocolVersion` で検索しても、`isCompatible` の呼び出しは `Pairing.swift:123` の `hello.protocolVersion` に対する1回だけであり、`welcome.protocolVersion` を比較する箇所はどこにもない。

構造的には「Mac が `hello` の版を弾いてから `welcome` を送る」（`MdoroServer.swift` の `.accept` 分岐、`:270`）ため、`welcome` が届く時点では版は既に一致しているという**間接的な**保証しかない。10.2 の `welcome.protocolVersion` および REQ-PRT-004 の「`hello` / `welcome` で交換し」という文言は、**送受信（wire上に載ること）としては満たされるが、welcome側の「検査」としては空文である。** テストも `serverMessagesRoundTrip`（`ProtocolTests.swift:36-55`）でエンコード/デコードの往復のみを確認しており、値の比較は検証していない。

**(b) REQ-PRT-004 の「両端末に更新を促す」は Mac 側でも果たされているか → 果たされていない。**
版不一致の `hello` は `Pairing.swift:123-125` で `.reject(.unknownDeviceToken)` として拒否される。この拒否は `MdoroServer.swift:295-309` の `refuse(_:of:to:)` に渡り、行われるのは
```swift
func record(refusal code: AuthFailureCode, of hello: HelloPayload) {
    diagnostics.write("conn.refused", level: .warn, [DiagnosticField("why", code.diagnosticSummary)])
}
```
という**診断ログへの記録のみ**である。`PairingView.swift` / `AppModel.swift` を検索したが、この拒否を Mac の画面に「更新してください」等として表示する経路は見当たらない。iPhone 側は `authFailed.code == .unknownDeviceToken` を受け取り、`ConnectionViews.swift:140` の
```swift
case .unknownDeviceToken: return "This device is no longer registered. Pair again"
```
を表示する — 版不一致であっても「再登録してください」という誤った案内になる（`AuthFailureCode` には版不一致を表す case が存在しない）。したがって Mac・iPhone のどちらの画面にも「更新を促す」文言は現れない。

**(c) TXT の版を探索段階で使っていないなら、TXT に版を載せる要件は何のためか → 現状、使われていない。**
`BonjourService.swift:17` のコメントは「so a version that cannot speak to this one is visible before a connection.」（=接続前に見えるようにする、が意図）と明言しているが、`DiscoveredServer.swift` の `ServerBrowser.read(_:)`（`:111-118`）は
```swift
nonisolated static func read(_ record: NWTXTRecord) -> (websocketPort: UInt16?, serverId: ServerID?) {
    (
        text(record, BonjourService.websocketPortKey).flatMap(UInt16.init),
        text(record, BonjourService.identityKey).flatMap(ServerID.init)
    )
}
```
と、`websocketPortKey` と `identityKey` のみを取り出しており、**`versionKey`（`"v"`）はどこにも読まれない。** `DiscoveredServer` 構造体自体にも version 用のフィールドがない。つまり TXT に版を載せるという REQ-COM-003 の要件は、書き込み側（advertise）でのみ満たされ、読み取り側（discovery/browse）では現状いかなる目的にも使われていない。

以下は私が読んだ範囲で気づいたものであり、**実装・起票はしていません。提案・懸念として、採用されていない前提で報告します。**
