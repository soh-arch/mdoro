## 表: `hello` ペイロードと「拒否として返るメッセージ」ペイロードの値域

対象は仕様書 10.2 節の一覧（`material-B.md` 927行目 `hello` / 957行目 `authFailed`）と、それに対応する実装（`Messages.swift` の `HelloPayload` / `AuthFailedPayload`）。

### `hello`（iPhone → Mac、**Mac が受け取る側**）

| フィールド | 型 | 値域 |
| :---- | :---- | :---- |
| `protocolVersion` | `Int` | **開いている**（整数。列挙ではない。`Messages.swift:59`） |
| `deviceToken` | `String?` | **開いている**（任意文字列。`Messages.swift:60`） |
| `pairingCode` | `String?` | **開いている**（任意文字列。`Messages.swift:61`） |
| `deviceName` | `String` | **開いている**（任意文字列。`Messages.swift:62`） |

### `authFailed`（Mac → iPhone、hello の拒否として返る側。**iPhone が受け取る側**）

| フィールド | 型 | 値域 |
| :---- | :---- | :---- |
| `code` | `AuthFailureCode`（enum, `String` rawValue） | **閉じている**（`invalidPairingCode` / `pairingModeNotActive` / `pairingAttemptsExceeded` / `unknownDeviceToken` / `connectionRejectedByUser` の5値。`ProtocolTypes.swift:213-223`。合成 `Decodable` は未知の raw String が来るとそこでデコード自体が失敗する） |
| `message` | `String` | **開いている**（診断用の任意文字列。`Messages.swift:119`。コメントにある通り送り手は自由文を書ける） |

## 問いへの答え

**Mac 側が受け取る側（＝`hello`）に、閉じた値域のフィールドは1つも存在しない。**
`HelloPayload` の4フィールドはすべて `Int` または `String` で、列挙型のフィールドが無い。

したがって、追記文「そこで未知の値を受け取っても」が想定している事象——**既知のフィールドに載る未知の値**（＝閉じた値域に属するはずのフィールドへ、列挙の外の値が来ること）——は、**この方向（版の違う相手からの `hello` を Mac が受ける方向）では、実装上そもそも発生しえない**。閉じた値域のフィールドが存在するのは `authFailed.code` だけであり、それは Mac が送って **iPhone が受け取る**フィールドである。つまり、この往復の中で「未知の値を受信しうる閉じたフィールド」を持つのは iPhone 側だけで、Mac 側には該当フィールドが一つも無い。
