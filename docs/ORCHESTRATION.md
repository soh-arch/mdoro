# ORCHESTRATION — オーケストレーターの手順書

**`CLAUDE.md` は規律を、このファイルは手順を書く。**
規律は「なぜそうするか」、手順は「毎回何をするか」である。

**この手順書は、オーケストレーターが誰であっても・どれだけ文脈を持っていても同じ結果になるように書く。**
記憶や気づきに依存する工程は、**道具に落とすか、表に落とす。**

**ここに書かれた工程を飛ばしたら、飛ばしたことを報告する**（`CLAUDE.md`「変更の通し方」）。

---

## 0. 委譲の境界

| 委譲してよい | 委譲してはいけない |
| :---- | :---- |

| 報告の裏取り（コマンドで決まる部分） | **`docs/PUNCHLIST.md` の更新**（台帳は正本） |
| 軸の提案（下の「天井」） | **人間への報告**（責任の所在が曖昧になる） |

## 2. 軸を決める — 二つの波

**床は常に、天井は必要なときだけ。二つは直列にしない。**
床の軸で1本目を投げ、**同時に**軸出しを走らせる。増えた軸があれば2本目を並列で投げる。

### 床（機械的に引く。判断を含まない）

**`python3 Tools/axes-for.py <base>` が下の表を読んで引く。**
表がこのファイルにあり、道具はそれを読むだけなので、**二重に持たない。**
**道具が引けない行は「自分で判断する」として出る。** 落ちない。

| 触った場所 | 必ず立てる軸 |
| :---- | :---- |

| `docs/decisions/` | **原典との一致**（要約・引用・覆した範囲）／`一部置換` / `superseded` の向きと書式 |
| `Packages/MdoroCore/` | **両端で共有されているか**（REQ-PRT-001）／プロトコルの前方互換（REQ-PRT-004 / 005） |

| **オーケストレーターが一次で書いた文章**（種類を問わず） | **記録との突き合わせ。** 要約が原典と一致するか、引用が逐語か、数えた数と書いた数が合うか |

## 3. 役に出す

- [ ] **指示書に自分の自己評価と結論を書かない。** 渡すのは**成果物・軸・環境の制約**。
      「何を直したか」「なぜそうしたか」を渡すと**指摘が減る**
- [ ] **「新しく見つける」依頼と「直ったか確かめる」依頼を分ける。**
      前回の指摘を並べると追認バイアスが働き、新規の発見が落ちる
- [ ] **環境の制約を毎回入れる**（下の定型）
- [ ] **実出力を報告に貼らせる項目を入れる**（`git log --oneline` / `git diff --stat` / `git status --short`）
- [ ] **提案・懸念・新たな選択肢は採用されていない前提で書く**、を入れる

### 環境の制約（そのまま貼る）

- **利用者がこの Mac で Mdoro を実際に使用中である。アプリを起動しない**
- **LAN に触れない**（変異実行で Bonjour の広告が 30ms 漏れた事故がある）
- **本物の Keychain / UserDefaults を汚さない**（注入の継ぎ目を使う）
- **`xcodebuild` には必ず `-destination` を付ける。** 省くと `Debug-iphoneos` としてビルドされ、
  **接続中の実機へ降りる**（2026-09-03 に発生）
- ビルドは `-derivedDataPath /tmp/mdoro-fix`。`swift test` は `Packages/MdoroCore` で走らせる
- **commit・push・PR は禁止**（役による）。作業ツリーを整えたら**申告する**
- シミュレータの `Application failed preflight checks` はテストの失敗ではない。
  `xcrun simctl shutdown all` の後に再実行する

### 並列にしてよいもの

**読むだけの検証は並列でよい。** **道具を使う検証は同時に1体だけ。**
ビルド資源（DerivedData・シミュレータ・実機）は単一で、2体が同時にビルドすれば踏み合う。

## 5. 自分が文章を書いたら

**ここが、この手順書がいちばん必要な工程である。**
落ち方はいつも同じで、**自分の要約が原典と違う。**
`05666f8` は、同じレコードの中で覆した箇所を「4箇所」と「3箇所」の両方で書いており、
**そのとき印は6箇所あった**（`git show 05666f8:docs/decisions/0011-claude-code-as-orchestrator.md | grep -c 0041`）。
**3つの数のどれも、数えれば出た。**

- [ ] **`python3 Tools/check-docs.py` を通す**（リンク・パス・要件ID・POL・欠番・版数と要件数）
- [ ] **数えてから書く。** 「3箇所直した」と書く前に数える。
      同じ commit の中で「4箇所」「3箇所」と食い違い、実際は6箇所だったことがある
- [ ] **引用は逐語で照合する**（`grep -o` で原典と突き合わせる）。記憶で引かない
- [ ] **要約した原典を読み直す。** 「〜だった」と書いた内容が、原典のどの節にあるか言えるか。
      **可能性を実績に格上げしていないか**（「入りうる構造だった」→「行っていた」）
- [ ] **記録に無い性格づけを足していないか**（「勝手に」など）

## 8. どこで走るか

**オーケストレーターはクラウドで走れる。** ローカルに縛られているのは、この Mac の資源に触る工程だけである。
**PC のスリープで作業が止まるほうが、往復が増えるより高くつく。**

| 工程 | どこで | 縛っているもの |
| :---- | :---- | :---- |
| 条文・Decision Record・この手順書・`docs/PUNCHLIST.md` の編集 | クラウドでよい | `git` と `python3` で足りる |
| 読み取りの監査（`spec-auditor` / `repo-auditor`） | クラウドでよい | 読むだけ |
| 軸出し（天井） | クラウドでよい | 渡すのは差分だけ |
| 実装（`MdoroCore` / Mac / iOS） | **ローカル** | `xcodebuild`・シミュレータ・実機・DerivedData は**単一**で、この Mac にしかない |
| 検証役のテスト実行・変異テスト | **ローカル** | 同上 |

**途中でローカルの資源が要るとわかったら、そこで止めて申告する。** クラウドから届かないものを
「届いたことにする」経路を作らない。

### クラウドからシェルを触るとき

**実行役（軽量なモデル）に渡し、判断させない。** 渡すのはコマンドで、頼むのは実行と貼り付けだけである。

- **出力は全文を貼らせる。要約させない。** 要約された時点で、裏取りが「読む」から「信じる」に変わる
- **数を主張に使うなら、何を数えたコマンドも書く。**
  `grep -c` は**行数**、`grep -o | wc -l` は**出現数**で、同じファイルに別の数を返す
- **打ち間違いは実行役では捕まらない。** 実行役は言われたとおりに実行するので、
  **間違ったコマンドの正しい出力**が返る。読むのはオーケストレーターの仕事である

### 承知のうえで失うもの

- **ビルドとテストの最後の一歩が、貼られた出力への信用になる。自分で叩き直せない**
- 1コマンドあたり1往復増える。**トークンは増え、速度は落ちる**
