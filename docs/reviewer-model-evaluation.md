**このファイルの用途**: オーケストレーター（このリポジトリの Claude Code）の
**コンテキストが溢れたときに失いたくない情報の置き場**である
（人間の指示・2026-09-07。それ以前はオーケストレーター引き継ぎのための資料だった）。

**会話の記憶を前提にしない。単体で読めるように書く。**
**プロジェクトの正本ではない。** 仕様は `docs/SPEC.md`、運用規律は `CLAUDE.md`、

## 1. 検証役とは何をする役か

`.claude/agents/reviewer.md` が正本。要点だけ再掲する。

- **独立コンテキストで成果物だけを見る。** 実装時のやりとりは渡さない
- **直さない。** 指摘を列挙する。commit・push・PR をしない
- 指摘には **根拠**（要件ID / `docs/CONTEXT.md` の項 / Decision Record 番号）、**場所**（`パス:行`）、
  **破綻する条件**（どんな入力・状態でどう壊れるか。再現できないものは「疑い」と明記）を付ける
- 最後に**実行したコマンドと結果**、**検証できなかった要件とその理由**を必ず書く

**この役が実際に何を見つけたかは §5 の教材が示す。**

## 2. 決まっていること

**2026-09-03、`CLAUDE.md`「権限」を書き換えた**（[0041](decisions/0041-a-role-answers-for-its-check.md)）。
**線は「どのモデルが作ったか」ではなく「役に何の権限があるか」で引く。**
外部ベンダーのモデルを検証役に据えること自体は、**条文上すでに許されている。**

**これは候補がどれでも変わらない。**

- **サブエージェントに完了承認の権限はない。「指摘なし」は merge の許可ではない**
- 検証役の出力は**指摘の列挙**であり、**採否はオーケストレーターが理由付きで判断する**（採らないなら理由を1行）
- **検証役は自分の検証に責任を持つのであって、成果物全体の品質に責任を持つわけではない**
- 仕様・設計の最終決定と merge は**人間のみ**

**したがって比較で決めるのは「信頼してよいか」ではなく、「どの軸で何を見つけるか」である。**

### 役がどのモデルで動くか

**`.claude/agents/reviewer.md` にだけ `model: sonnet` がある。他の役ファイルには `model:` が無い。**
**既定のモデルを指定する設定ファイルは、プロジェクト側にも利用者側にも存在しない**（2026-09-07 に確認）。

したがって:

- **検証役は Sonnet で動く**（2026-09-03 の裁定。**運用したい水準そのものを基準にするため**であり、
  深い1本が要るときは**呼び出し側でモデルを上書きする**。**これは既定を下げる変更である**）
- **オーケストレーターがその場で立てた役**（`general-purpose` など）は、**親のモデルを継ぐ。**
  2026-09-07 の候補調査を行った2体は **Opus 5** であった（セッション情報で確認）

**「サブエージェント＝ Sonnet」ではない。** 役ファイルを持つ役と、その場で立てた役で違う。

## 3. 候補モデル —— 確定（2026-09-07）

**選定の基準**: **対照群（Claude Sonnet 5）と同じ価格帯に揃える。**
最上位どうしを比べると「モデルの格差」と「検証役としての適性」が混ざり、
**「同じコストなら誰が検証役として使えるか」という運用に直結する問い**にならないため。

**上限は Kimi K3 のトークン単価（入力 $3 / 出力 $15）**とする（人間の指示・2026-09-07）。
**全候補がこの内側に収まっている。**

| 枠 | 指定する識別子 | 文脈長 | 入力 | 出力 |
| :---- | :---- | ----: | ----: | ----: |
| 米国・OpenAI | `openai/gpt-5.6-sol` | 1,050,000 | $2 | $10 |
| 米国・Meta | `meta/muse-spark-1.3` | 1,048,576 | $1.25 | $4.25 |
| 米国・xAI | `x-ai/grok-4.6` | 500,000 | $2 | $6 |
| 中国・Alibaba | `qwen/qwen3.8-max-0902` | 1,000,000 | $2 | $6 |
| 中国・DeepSeek | `deepseek/deepseek-v4-pro-0813` | 1,048,576 | $1.049 | $3.148 |
| 中国・Moonshot | `moonshotai/kimi-k3`（**Moonshot AI 提供・mxfp4**） | 1,048,576 | $3 | $15 |
| **対照群** | `anthropic/claude-sonnet-5` | 1,000,000 | $2 | $10 |

価格は百万トークンあたり。**米国3・中国3の均衡。** 比較にのみ OpenRouter を使う
（実運用に採るなら、API の従量課金かサブスク契約での CLI 起動になる）。

### 指定の作法

- **`~` で始まる識別子は使わない。** OpenRouter では**先頭の `~` が「中身の入れ替わる別名」の印**である
  （`~x-ai/grok-latest` など）。再現できない実行になる
- **日付付きの版を指定する。** `deepseek/deepseek-v4-pro` は 2026-04-24 の**別の版**であり、
  `-0813` が 8月の版である。日付なしを掴むと古いものが走る
- **Kimi K3 は提供事業者をベンダー自身に固定する。** 理由は下記

### Kimi K3 の量子化 —— 前提が逆である

**MXFP4 が公式重みそのものであって、劣化版ではない。**
技術報告書（`github.com/MoonshotAI/Kimi-K3` の `k3_tech_report.pdf` §4.1.4）によれば、
Moonshot は MoE 専門家重みを MXFP4 に量子化したうえで、
**教師あり微調整と強化学習を含む後学習の全期間にわたって量子化認識学習を行っている。**
学習時と推論時で量子化方式が一致するよう設計されており、**BF16 のチェックポイントは配布されていない。**

したがって OpenRouter で「bf16」を掲げる事業者が提供しているのは、
**MXFP4 を逆量子化して持ち上げたものか第三者の再量子化版**であって、より高精度の原本ではない。
**「bf16 ＝ 最高精度」という直感は、このモデルには当てはまらない。**

### 候補から外したもの（理由を残す）

| 外したもの | 理由 |
| :---- | :---- |
| **GPT-6 Astra**（$10 / $50） | **推論の可視性が構造的に下がる方向。** OpenAI 自身が「思考連鎖による監視が Sol より難しい」「推論を言語化せずに難しい課題を解ける」「推論トレースに何を出すかを強く制御できる」と記している。検証役は「なぜその指摘に至ったか」をオーケストレーターが読める必要がある。**なお単価が5倍でもタスク単価は5倍にならない**（Artificial Analysis の測定で Sol より70%トークン効率が高い）ので、**単価だけを理由に外したのではない** |
| **GLM 5.3**（$1.4 / $4.4） | **長さ制約の遵守が候補中最悪。** 議論ベンチマークで強制切り詰めが 18.2%（Kimi K3 5.5%、DeepSeek 3.5%、Qwen 0.0%）。**指示を受ける役として明確な減点。** 加えて OpenRouter の文脈長 1,310,720 は**事業者側の設定であってベンダー値ではない**（チェックポイント上限は 1,048,576、Z.ai 公式 API は 1,000,000）。**ライセンスが GLM-5.2 の MIT から独自のものに変わっており、本文を確認できていない** |
| **Llama 系** | **Meta の最新は Muse であり、Llama 4（2025-04-05）はその前の系列。** 系列そのものが交代している |
| **Trinity**（Arcee AI、$0.25 / $0.80） | 価格帯が明らかに下で、文脈長も 262,144 と狭い。**対照群と同格に揃えるという基準に合わない** |

**Grok 4.6 は、いったん外してから戻した。** 外した根拠は Grok **4.5** の「判断を下さない率 64.1%」だったが、
**それは2世代前の測定であり、4.6 は未測定である。**
**測定していないものを推定で決めない**という理由で復帰させた（人間の判断・2026-09-07）。
**同じ理屈が Qwen3.8 Max にも当てはまる**（§4 参照）。

## 4. 事前調査で分かったこと（2026-09-07）

> **信頼度の但し書き。** 調査した2体（Opus 5）は、**ほとんどの一次資料に直接アクセスできなかった。**
> 組織のネットワーク方針により、OpenAI・Meta・xAI・Anthropic の公式サイト、Artificial Analysis、
> arXiv、Hugging Face が遮断されている。**届いたのは `platform.claude.com` と GitHub だけ。**
> 以下の大半は、検索エンジンの要約か、GitHub 上にあった一次資料の複製である。
> **転記誤りの可能性が一段分残る。**

### 4.1 判断率 —— この比較の主軸

**同じベンチマークの表である**（LLM Sycophancy Benchmark、`github.com/lechmazur/sycophancy`）。
同じ紛争を対立する2人それぞれの視点から語らせ、判断が語り手に付いて回るかを測る。
**`INSUFFICIENT` は判断を拒否した割合、`Decisive Coverage` は両視点で立場を取った割合。**

| モデル | 判断を拒否 | 両視点で立場 | 迎合率 | 逆張り | 備考 |
| :---- | ----: | ----: | ----: | ----: | :---- |
| **Kimi K3** | **4.7%** | **90.4%** | 4.5% | 16.2% | **本人の測定** |
| GPT-5.6 Sol | 22.6% | 73.7% | 3.0% | 15.7% | 本人の測定 |
| **Claude Sonnet 5**（対照群） | 22.5% | 69.7% | 9.1% | 6.6% | 本人の測定 |
| GLM-5.**2** | 17.7% | 73.7% | **12.6%** | 9.1% | 5.3 は不在・前版で代用 |
| DeepSeek V4 Pro | 38.0% | 46.0% | 5.1% | 3.6% | 版の記載なし |
| Qwen 3.**7** Max | **61.5%** | **29.8%** | 1.5% | 5.6% | 3.8 は不在・前世代で代用 |
| Grok 4.**5** | **64.1%** | 30.3% | 0.0% | 3.0% | 4.6 は不在・前世代で代用 |
| *（参考）Claude Fable 5* | 27.0% | 77.3% | 0.5% | 20.4% | — |

**⚠ この2列を足し引きして読まないこと。** 「判断を拒否」と「両視点で立場」は、同じ母集団の上の補数ではない。
このベンチマークは **198件の紛争を5つの視点で問う**（Coverage の分母 990 = 198 × 5 と合う）ので、
**前者は応答ごと、後者は紛争ごとに数えている可能性が高い。**
実際、**Claude Fable 5 の行では両者の和が 104.3% になり、100% を超える。**
**一次資料に到達できないため、集計の単位を確かめられていない。** 列どうしの引き算はしないこと。

**ベンチマーク著者自身の注意**: 低い迎合率は「安定した判断」「棄権」「その両方」のいずれでも生じうる。
**`Decisive Coverage` と併読せよ。**

**Qwen 3.7 Max の迎合率 1.5% は、61.5% が判断しないことの裏返しである。**
Grok 4.5 を外した根拠と同じ形の懸念が Qwen にもあるが、**どちらも前世代の測定なので、走らせて確かめる。**

### 4.2 幻覚

- **GPT-5.6 Sol は AA-Omniscience で幻覚率 92%**（max effort）。GPT-6 Astra は 51%。
  **知らないことを問われたとき、9割以上でっち上げる**と読める
- **Grok 4.6 の非幻覚率 65.7%** —— 知らないとき3回に1回は捏造する
- **Kimi K3 の内製ベンチ Faithfulness 85.5**（GPT-5.6 Sol 84.8、Opus 4.8 83.6、GLM-5.2 74.8）。
  **内製・非公開のため再現性はない**
- **Claude Sonnet 5 は MASK（追従的不誠実さ）で嘘をつく率 3.1%** —— 試験された Claude 系で最低
  （Opus 4.8 6.1%、Sonnet 4.6 13.3%）

### 4.3 検証役に向く／向かない性格

- **Muse Spark 1.3**: Meta 自身が「**曖昧なときは質問を返し、行き詰まったら助けを求め、
  でっち上げる代わりに分からないと言う**」よう訓練したと公式に述べている。
  Artificial Analysis でも**棄権率の上昇**が確認されている。
  **幻覚は減るが、指摘を列挙させる役としては「質問が返ってきて指摘が出ない」失敗になりうる**
- **DeepSeek V4 Pro**: **順序バイアスが大きい。** 同じ2案を順序を入れ替えて見せると
  **43.6% で勝者が入れ替わる**（Position Bias Benchmark、36モデル中19位）。
  一方で**同一入力に対しビット単位で同一の出力を返すカーネルを実装したと公表している唯一のモデル**でもある
  （技術報告書 §3.3）。ライセンスも候補中唯一の MIT
- **Qwen3.8 Max**: **IFBench 82.8** は Qwen 自身の表で全モデル中最高（Opus 4.8 62.2、Sol 72.7）。
  議論ベンチでも**強制切り詰め 0.0%** と書式追従は最良。ただし**議論の中身は候補中最弱**。
  公式資料が **`presence_penalty` を上げると言語混在が起きる**と明記している
- **Claude Sonnet 5**: コードレビュー特化の第三者測定（CodeRabbit）で
  **精度 29% → 38〜40%、バグ検出率 57% → 50〜51%。**
  評は「**少なく鋭いコメントが欲しいときに選べ**」
- **Grok 4.6**: 第三者が「xAI の宣伝は勝っている行だけを読んでいる」と指摘。
  **純粋なソフトウェア工学系の評価では GPT-5.6 Sol に負ける**（DeepSWE 7.1pt、Terminal-Bench 8.6pt）。
  **20万トークンで課金が2倍になる段差がある**

### 4.4 日本語

**候補6体のいずれについても、日本語性能の定量測定は見つからなかった。**
中国系4社は公式資料に日本語の記述が一切なく、GLM は対応言語を英語と中国語の2つだけと宣言している。
DeepSeek は中国語 84.4 に対し英語 57.9（Chinese-SimpleQA / SimpleQA-Verified）と、
**中英の差が候補中最大**であり、実世界評価も全面的に中国語である。
**20万バイト級の日本語仕様書を読ませる用途では、これは中立な材料ではない。**

### 4.5 横断的な注意

- **各社のモデルカードの数値を横に並べる比較は成立しない。**
  同じベンチマーク・同じモデルで、Z.ai と Moonshot が別の数字を出している実例がある
  （Kimi K3 の AutomationBench が 46.7 と 30.8、GDPval-AA v2 が 1682 と 1686）。
  **自分で走らせる意味はここにある**
- **Artificial Analysis の Intelligence Index は v4.1 と v4.2 で数値が食い違う。**
  同じモデルに2系統が流通しており、混ぜると順位が逆転する
- **査読付き論文が1本ある**（Automated Software Engineering 誌、arXiv:2603.00539）。
  要件適合性の判定において、**LLM は正しい実装を頻繁に「不適合」と誤判定する**（系統的な過剰修正）、
  **プロンプトを詳細にするほど——特に説明と修正案を求めるほど——誤判定率が上がる**、
  **説明そのものが一貫して信頼できない**（症状の認識は高いが原因の特定は弱い）。
  **この結果は「検証役は直さない」「採否はオーケストレーターが判断する」という現行の規律が、
  実測された失敗モードに対して正しい向きの防御になっていることを示唆する**

## 5. 第一段（条文テスト）—— 教材と、期待される指摘

**教材E を除き、git に実物がある。** 抽出コマンド:

```bash
git show <hash>:docs/SPEC.md | grep '^| \*\*REQ-PRT-005\*\*'
```

**第一段で使うのは A・D・E の3本である**（B・C はリポジトリを読まないと解けないため、第二段以降）。

### 教材A —— `6308396`（REQ-PRT-005 追記の1稿目）

> **既知のフィールドに載る未知の値は、これに当たらない。** プロトコル版が完全一致しなければ接続は成立しない
> （REQ-PRT-004）ため、**同じ版の中に現れた知らない値は、新しい相手ではなく異常である**
> （版を上げずに値を足した、あるいは壊れている）。REQ-ERR-009 の破損メッセージとして扱い、破棄して数えること。

**期待される指摘（major）**: 根拠が**証明しすぎている。** 「版が一致しなければ繋がらない」は
**未知のメッセージ種別にもそのまま当てはまる**ので、同じ条文の前半（前方互換性＝未知の種別は無視する）が
空文になる。同じ理屈で未知の種別も「数える」ことになり、**将来の Mac が新しい種別を10通送っただけで
古い iPhone が再接続ループに入る。**

**副次**: 「版を上げずに値を足した」は、**どの条文にも Decision Record にも無い前提**である
（「値を足したら版を上げる」という一般則は存在しない。POL-184）。

### 教材B —— `b79b76c`（2稿目・前半）※第二段以降

Aに「**版の違う2台が唯一やり取りするのは `hello` とその拒否までであり**、そこで未知の値を受け取っても
線はそのまま終わるので、数えることに実害はない」を足したもの。

**期待される指摘（major）**: **「唯一」が誤り。** `MdoroServer.handle` は**認証前にすべての
クライアントメッセージ種別を処理する** —— `timeSyncPing` に応答を返し、`heartbeat` を記録する
（門があるのは `command` と `requestSnapshot` だけ）。**コードを読まないと出ない指摘。**

### 教材C —— `44ee360`（3稿目）※第二段以降

> …**ただし拒否（`authFailed`）を握り潰してはならない** —— 理由の語が読めなくても、**拒否されたこと自体は
> 利用者に示すこと**。REQ-PRT-004 は非互換のとき両端末に更新を促すことを求めており、**拒否は捨てたら
> 次が来ない最後の1通である**。

**期待される指摘（major・複数）**:

1. **この例外条項は不要である。** 10.2 は非互換を **`error.code` の `protocolVersionMismatch`** に
   割り当てており、`authFailed.code` の一覧には無い。**条文どおりならその値は全版のカタログにあるので
   握り潰しは起きない。** 懸念の実体は**実装の逸脱**（`Pairing` が非互換を `authFailed(.unknownDeviceToken)`
   で返している）であって、条文の穴ではない
2. **新しい義務である。** 「拒否されたこと自体を示せ」は `authFailed` **全般**を縛るが、
   REQ-PRT-004 が語るのは非互換の場合だけ。しかも「更新を促す」より**弱い**
3. **争点だった「数える」の理由が空白になった。** 新しい根拠（寄せて読むと偽られる）が支えるのは
   「寄せて読むな」までで、「数える」を支えない

### 教材D —— `b95b38d`（閉じた集合で線を引こうとした稿）

免除の非適用を、閉じた集合のフィールドに限定したもの。

> **この免除は、値の集合が閉じているフィールド**（`type` / `code` / `action` / `event` など、条文と 10.2 が取りうる値を列挙しているもの）**に載る未知の値には及ばない。**

**期待される指摘（major）**: **例示に `type` を入れたことで、前半を取り消している。**
